# 五状态与显式归档

2026-11-07 用户要求取消已完成状态，只保留待归档，并在卡片上提供直接归档按钮。

界面、导航和状态选择器仅提供待判断、进行中、待审阅、已阻塞、待归档。
旧数据库的 completed 投影为 to_archive，保留备注、版本、输入提示和历史。
存储层继续接受旧状态，供旧调用方兼容；新界面不会再写入 completed。
原生轮次的 completed 与 completedAt 仍表示执行结束，自动流转仍进入待审阅。
五状态分区配置不再要求 completed，旧六状态配置仍可载入。
旧 completed 会话显示在待归档列；原生分区权威模式不后台搬迁既有位置。

只有待归档卡片显示“归档”按钮，点击直接调用 POST /api/archive。
HTTP 与 MCP App 共用后端。请求必须包含已发现会话 ID、状态版本和输入版本。
原生分区权威模式还携带原生位置，并在归档前独立读回真实待归档位置。
后端拒绝过期编辑、未复核新输入和其他状态。同一会话操作串行；
没有全局分区同步锁，其他会话的慢移列、归档或标题请求不阻止本次归档。
归档使用配置中的桌面 socket 和独立 ArchiveWriter，只允许 initialize、
thread/list、thread/read、thread/turns/list、thread/archive。原读取连接和标题连接权限不变。

调用前先完整分页读取已归档列表，找到账户当前桌面上的同一 ID 即确认归档，
不会再次写入。否则读回目标 ID 与原生状态，仅 idle 或 notLoaded 可以归档。
另完整读取原生最新轮次中的用户消息，核对当前确认的轮次 ID 和用户消息 ID，
即使观察器尚未落库也能拒绝未核对的新输入。无法取得有效读回时拒绝归档。
thread/archive 的有效成功回执才允许提交本地归档标记。
失败或丢回执保留卡片和备注，显示失败或结果待确认；用户再次点击时先读回，
包括进程在远端成功、本地提交前退出的情况。不会自动归档其他待归档卡片。
单次归档连接包括分页、预读和写入在内共用最多三秒的预算。

原生模式先短事务检查，再在数据库锁外执行原生请求，最后重新检查并保存归档标记、
清理队列。远端成功而本地未确认时报告结果待确认，重试先查询实际归档结果。
重启、迟到扫描和观察结果不会恢复已确认卡片。程序保留备注和变更历史，
停止该卡片的标题和执行状态处理。旧本地兼容模式保留原事务边界。
本轮未实现从看板取消归档；原生客户端取消归档后，本地确认标记仍保留。

官方协议依据：
https://developers.openai.com/codex/app-server/
文档说明 thread/archive 把会话日志移入归档目录，成功返回空对象，
并尝试归档其派生子会话日志。本实现不另行发送模型消息。

## 验收差异与证据边界

保留 acceptance-v1 的 31 条编号、需求、独立模型和锁，不改写其历史含义。
冻结 STATE-001 仍写六状态，BOUNDARY-001 仍禁止真实归档，属于本次明确变更的旧边界。
兼容存储的冻结测试不能证明新界面符合六状态，也不能签收真实归档扩展。
新增 tests/archive_flow.rs 覆盖五状态投影、持久化、并发版本和新输入保护、
失败与丢回执重启后确认、原生状态保护、MCP 接线与隔离桌面协议端到端归档。
原生操作仍需在目标客户端验证五列、按钮单击、实际归档结果和刷新、重启读回。
未取得这些真实证据前保持 release_ready=false。
