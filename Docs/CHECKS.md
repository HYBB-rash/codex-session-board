# 项目约束检查

任务结束和会话结束前统一运行：

```bash
./scripts/check
```

无需先阅读脚本。检查失败时会显示问题和下一步命令。退出码为 0 表示通过，
1 表示规范不满足，2 表示执行出错。检查默认只读，不暂存、提交、推送或部署。
入口使用 Bash，实际检查逻辑使用 Rust；需要 Git、Cargo 和已下载的锁定依赖。

## 当前规范

1. Git 工作区必须干净：暂存、未暂存、删除和未跟踪文件均算未提交变更。
   子模块的变更也检查。`.gitignore` 中的构建产物、本机配置和运行数据不需要提交。
2. 每次提交必须恰好前进一个版本，包括文档、测试、整理及空提交。
   `Cargo.toml` 与 `Cargo.lock` 的项目版本必须一致。
   第三段为 0–99，第二段为 0–9，满后自动进位，第一段持续增长。
   不允许跳号、重复版本、回退版本或人工阶段升版。
3. 提交前必须通过测试。统一检查入口确认项目 Git 钩子已经启用，
   实际测试由 `pre-commit` 钩子在提交前运行。
4. 项目自身 Rust 代码禁止使用 `unsafe`。`Cargo.toml` 使用
   `[lints.rust] unsafe_code = "forbid"`，由编译器在构建与测试时执行，
   不能通过局部 `#[allow(unsafe_code)]` 降低限制。
5. 正式代码禁止使用 `.unwrap()` 和 `.expect()`。使用 Clippy 官方的
   `unwrap_used = "deny"` 与 `expect_used = "deny"` 检查；
   `clippy.toml` 允许测试代码使用这两个方法。
6. 每个函数最多 41 行。使用 Clippy 官方的 `too_many_lines = "deny"`，
   在 `clippy.toml` 设置 `too-many-lines-threshold = 41`。
   行数按 Clippy 的规则统计；测试、示例和检查脚本中的 Rust 函数也受限制。
   提交钩子运行全目标 Clippy，超限即阻止提交。
7. 代码应当自解释，不新增普通 Rust 行注释和块注释；业务、测试、示例及
   Rust 检查器代码均适用。暂时允许 Rust 文档注释。既有普通注释只报告，
   不要求为了通过检查而删除。识别使用 Rust 编译器的词法分析器，
   不通过搜索 `//`、`/*` 判断，因此字符串中的这些内容不会误报。
8. 根目录只保留 `AGENTS.md` 和 `README.md` 两个文档文件；其他根目录
   项目文档放到 `Docs/`。检查只报告违规文件和处理建议，不自动移动或删除。
9. 提交前按实际暂存区检查规模：文本新增行数加删除行数不超过400，
   文件数不超过13，400行和13个文件均允许；统计范围与特殊情况见“提交前检查与规模”。

基线、旧用户阶段决定及自动进位切换点保存在 `project-rules.json`。
迁移前已发布基线为 v0.1.0，首个 Git 提交使用 v0.1.1。
`versioning.rollover_after` 固定为切换前的完整父提交号，
旧提交继续按当时的规则验证；切换点不能移动、删除或在合并时撤销。
后续约束继续加入检查脚本，`AGENTS.md` 简短说明开发风格和检查入口。

## 根目录文档位置

默认的 `./scripts/check` 逐项检查根目录文件，包括未跟踪或被 Git 忽略的文件。
只允许 `AGENTS.md` 和 `README.md` 这两个精确文件名；目录及其内容不在本项检查范围，
因此 `Docs/` 中的文档和程序使用的 `execution-templates/` 保持各自用途。

按以下明确的文件名规则判断文档，不读取内容猜测用途：

- 文档扩展名：`.md`、`.markdown`、`.mdown`、`.mkd`、`.mdx`、`.rst`、`.rest`、
  `.adoc`、`.asciidoc`、`.org`、`.rdoc`、`.txt`、`.text`、`.pdf`、`.doc`、`.docx`、
  `.odt`、`.rtf`、`.tex`，扩展名不区分大小写。
- 无扩展名的常见文档名：`README`、`CHANGELOG`、`CHANGES`、`HISTORY`、
  `CONTRIBUTING`、`INSTALL`、`USAGE`、`DESIGN`、`ARCHITECTURE`、`TODO`、
  `FAQ`、`NOTES`，不区分大小写。
- 程序输入文件 `CMakeLists.txt`、`requirements.txt`、`constraints.txt`、
  `meson_options.txt` 明确排除；以 `requirements-`、`requirements_`、
  `constraints-`、`constraints_` 开头并以 `.txt` 结尾的输入文件也排除，
  例如 `requirements-dev.txt`，名称不区分大小写。
- 其他文件不因内容像文档而被认作文档；Cargo 清单和锁文件、JSON/TOML/YAML 配置、
  CSV 数据、HTML 资源、源码、脚本等保持原位。

发现违规时列出文件名并提示移到 `Docs/`；目标存在同名文件时先比较内容，不覆盖。
本文及其他项目文档里的命令、源码和运行数据路径仍以项目根目录为基准。

## 代码表达与注释

优先用清晰的命名、合适的类型、简单的函数结构和测试表达程序行为。
遇到新增普通注释，先判断哪些命名、类型或函数结构需要改善，再用测试验证行为；
不要机械删除注释，也不要把它改成文档注释来绕过规则。

默认的 `./scripts/check` 包含注释检查；开发中可以只运行这一项：

```bash
./scripts/check --comments-only
```

词法分析依赖 `ra-ap-rustc_lexer`，这是 Rust 编译器 `rustc_lexer` 的自动发布版本，
版本固定在锁文件中。它区分普通注释、文档注释和字符串，支持嵌套块注释。
普通字符串、原始字符串、字节字符串和 C 字符串中的注释符号均不算注释。
未闭合的注释或字符串等词法问题会报错，不当作“没有注释”放行。

`project-rules.json` 的 `rust_comments.baseline_commit` 固定为规则启用前的
`f0fd5d3d208d018b00ae04dbe7e22151bcac518a`（v0.1.4）。
从该 Git 提交读取既有普通注释；不自动刷新基线，不把之后的 HEAD 当成新基线。
按相对文件路径、完整注释文本及出现次数比较：原样保留、在同一文件移动或删除不会
触发新增问题；改写注释、复制出更多份、放到新文件均算新增。
删除或改写既有注释仍须根据实际需求决定，检查器不会代做。
缺少基线提交时应补全 Git 历史，不能改成当前提交来绕过检查。

检查覆盖 Git 管理的所有 `.rs` 文件及未忽略的新 `.rs` 文件，包括测试、
示例和检查器；按 Git 忽略规则排除未跟踪的构建产物及运行数据。
输出包含文件、行号、基线和现有注释数量，以及先改善代码表达、再验证行为的建议。
普通注释检查通过只说明满足这条机械规则，代码是否容易理解仍需开发和审查判断。

检查遍历当前 HEAD 可达的全部提交，包括已合并分支，不仅检查最近一次提交。
各提交相对第一父提交计算一次版本步进，合并提交也算一次。浅克隆必须补全历史后再检查。
历史上已有不合规提交时，会明确报错；不会通过再补一次升版来掩盖旧问题，
也不会自动改写历史。

## 提交前检查与规模

```bash
./scripts/check --pre-commit
```

该模式读取本次实际提交的索引（index），包括 Git 为路径限定提交使用的替代索引，
导出暂存快照；连 Rust 检查器的编译也基于暂存快照，未暂存的修复不能代替已暂存的内容。
检查提交规模、候选版本及完整历史、普通注释、根目录文档、禁止 `unsafe` 的配置，
并检查钩子启用状态与暂存钩子的存在及执行权限。候选版本须为下一补丁版，
或有匹配用户决定记录的下一阶段版本，且清单与锁文件一致；本模式不要求工作区干净。
默认 `./scripts/check` 仍检查工作区干净、当前版本与 HEAD 一致及完整历史，不替代提交前模式。

规模按 HEAD 与实际索引的差异统计，无 HEAD 时与空树比较。
使用 Git 的 `diff --cached --numstat -z` 统计，按空字节分隔文件记录，识别重命名的相似度设为50%。
文本新增行数加删除行数最多 400 行、文件最多 13 个，均含边界：

- 所有源码、测试、文档、脚本及 `Cargo.toml`、`Cargo.lock` 等配套修改均统计，不按用途排除。
- 新文件计全部新增行，删除文件计全部删除行；替换一行通常计新增1行加删除1行，不能按净增量抵扣。
- Git 识别的重命名算一项文件变更；纯重命名为0文本行，有内容修改时计其新增和删除。
- 二进制文件计文件数，另提示无法按文本行数衡量，不计入文本行合计。
- 空文件和仅权限变化也计文件数，即使文本变更为0行。
- 未暂存修改、未跟踪文件及 `git add -N` 的意向添加不计；属性文件按暂存快照读取，
  未暂存的 `.gitattributes` 不影响统计分类。

超限时按独立、可验证的步骤拆分提交，保留有用改动，不通过删除文件或扩大忽略规则凑上限。
该模式不替代钩子的全目标 Clippy 和测试；`--comments-only` 仍支持单独检查普通注释。

## 普通提交

完成修改后准备本次版本：

```bash
./scripts/check --prepare-commit
```

该命令只同步本次应提交的版本，不提交代码，也不修改第三方依赖版本。
重复运行不会再次加号。接下来按顺序操作：

1. 选择本次应提交的文件或片段，暂存代码、版本文件及适用的阶段决定。
2. 用 `git diff --cached` 审阅实际候选内容，确认改动范围正确。
3. 运行 `./scripts/check --pre-commit`，通过后才可在获得提交授权的前提下提交。
4. 提交钩子再次运行统一提交前模式、Clippy 和测试，全部通过才允许提交。
5. 提交后运行普通 `./scripts/check`，按提示处理剩余未提交改动。

本机存在 `agent-git` 时，Agent 使用 `agent-git commit`；否则使用 `git commit`，
不修改用户的签名配置。

准备成功不代表工作区检查通过：新版本和其他改动都提交后，默认检查才会通过。

## 自动进位版本

2026-11-07 用户将人工阶段升版改为自动进位。准备命令保持为：

```bash
./scripts/check --prepare-commit
```

例如 v0.1.99 的下一版为 v0.2.0，v0.9.99 的下一版为 v1.0.0，
v9.9.99 的下一版为 v10.0.0。第一段在存储整数范围内持续增长，溢出时报错。
只接受无前导零的三段整数，不接受预发布后缀或手工越界值。
从 HEAD 计算下一版，重复准备、检查或失败重试不会重复加号。
自动进位后拒绝 `--feature-complete`；旧阶段决定仅用于旧历史验证。

版本仅表示迭代顺序，不表示兼容性、阶段完成、成熟度或验收通过。
外部依赖工具仍可能按 SemVer 解释兼容范围，公开库应单独管理其兼容性。
并行分支可能得到同号；集成时按最终父提交重新准备，发布版本须对应确定内容，
定位构建同时核对 Git 提交或构建哈希。撤销代码形成新提交，继续递增；
部署回滚保留旧产物原编号，不改写已发布版本内容。
程序版本与数据库、配置及协议格式版本独立，进位不触发格式升版。

## 提交前自动测试

运行一次安装命令，为当前仓库启用 Git 钩子：

```bash
./scripts/install-git-hooks
```

钩子源文件为 `.githooks/pre-commit`，随代码保存；安装命令仅设置当前仓库的
`core.hooksPath`，不修改全局 Git 设置。重新克隆后需要再次安装。
已有其他钩子配置时会停止安装，避免覆盖。

每次提交前，将实际索引导出到临时目录，先运行 `./scripts/check --pre-commit`，
统一检查规模、候选版本、历史和上述适用规则，
再运行 `cargo clippy --all-targets --locked --offline -- -D warnings`，
再运行 `cargo test --locked --offline`。
全部通过后才允许提交；统一提交前检查、Clippy、测试失败或无法运行均会阻止提交。
第一次测试前需要准备好 Rust 工具链与锁文件对应的依赖。
当前测试包含单元测试、命令行和契约测试及检查器自身测试，不连接线上服务。

测试针对即将提交的代码，不受未暂存修改影响；不修改工作区或暂存区。
临时目录自动清理，构建缓存默认复用当前仓库的 `target`，
也可以通过 `CARGO_TARGET_DIR` 指定缓存目录。
检查脚本仍在会话结束时以默认模式运行，检查文档位置、注释、工作区、版本规则和钩子启用状态；
提交钩子复用 `--pre-commit` 模式，不要求工作区干净，但会检查暂存候选版本。

## 验证检查器与钩子

```bash
cargo test --locked --offline --example project_check
cargo test --locked --offline --test git_hooks
```

测试在临时 Git 仓库中构造提交，覆盖未提交文件、逐次升版、历史违规、
锁文件版本不一致和阶段完成决定，以及函数 41 行允许提交、42 行拒绝提交的边界；
不会提交当前项目或访问线上服务。
注释测试覆盖真注释、字符串中的注释符号、文档注释、已有注释与新增注释、
重复及改写、Git 基线和暂存快照，确保未暂存内容不能掩盖将提交的普通注释。
文档位置测试覆盖允许的根目录文档、文档扩展名与大小写、无扩展名文档、
程序输入例外、配置和数据文件、目录及嵌套文档，并验证检查不会移动或改写文件。
提交规模测试覆盖400/401行、13/14个文件、新增删除、重命名、二进制、空文件和权限变化，
以及部分暂存、未跟踪文件、意向添加与未暂存属性文件不污染暂存快照的边界。
