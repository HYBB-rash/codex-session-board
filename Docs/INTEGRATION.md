# 提交、PR、集成候选与发布

2026-11-14 起，按用户明确授权执行分层规则。
历史提交继续按自身记录的版本规则检查，不改写历史。

## 开发提交

保留最多 13 文件、400 行的改动规模限制。
提交钩子检查实际暂存快照、注释、清单、版本和检查设置，不要求整项功能可交付。
Clippy、业务测试和检查工具自测不在每个提交重复执行。
普通提交保持现有版本；`--prepare-commit` 在新规则下不会增加版本。

## PR

一个 PR 说明一个明确目的、改动范围、相关验证及依赖。
代码审阅包含业务变化、测试绑定和数据保护。
开发者只更新本任务记录，不竞争修改版本清单或共享状态。
原始小提交保留，不由协调者逐个重放。

## 集成候选

固定主线和原 PR 头，使用隔离工作树集中整合。
合并时分别审核带入的开发提交和手工冲突修改，不能以提交标题取得豁免。
完整门禁绑定最终源码和提交身份；缺失、跳过或失败不能视为成功。
合并门禁只检查工程自动部分和实际包的隔离启动，不安装或重载日用客户端。
最终组合通过、受保护主线确认同一候选且双平台不可变插件包可用，合并任务即完成。
安装、当前客户端加载、真实界面及远端功能验收属于后续独立任务。
候选改变后，之前的通过记录不替新候选签收。
有依赖的 PR 一起处理；独立失败项可以移出，重新验证剩余组合。
主线在候选完成后若前进，重新整合和验证，不强制推送。

## 发布

协调者在完成合并后运行 `./scripts/check --prepare-release`。
该操作记录绑定源码父提交的升版意图，并统一更新四个版本清单。
再次执行不会重复增加版本。
冻结候选后执行组合验证和打包，部署同一不可变产物。
完整 31 条验收及外部证据门槛继续保留，候选自动通过不等于 release_ready。
部署任务如按用户授权携带既有缺证，必须明确记录，不能冒称完整验收完成。

## 实际入口

发布前快速检查运行 `./scripts/validate --scope preflight --output /tmp/preflight-result`。
它只打包与解包源码、比对完整实现指纹、版本和入口执行权限，不编译或启动插件。
候选CI也在完整验证前调用此入口。结果不是完整候选门禁，不能用于提升主线。

安装后的独立生效检查运行
`./scripts/verify-plugin --client-pid CLIENT_APP_SERVER_PID --expected-source RELEASE_SOURCE_SHA --config-id EXPECTED_CONFIG_ID --output /tmp/plugin-proof.json`。
默认只读，核对安装与缓存全部文件、实际HTTP服务身份、配置和数据目录、
MCP可执行文件、所选客户端的父子进程关系及检查期间进程身份未变化。
不根据旧安装回执或无关守护进程宣称当前客户端加载成功。
退出0表示已核实，退出2表示已安装但仍待当前客户端加载，退出1表示核验失败。
可选`--reconnect`复用更新工具已有的定向重连；没有受支持的当前桌面连接时仍返回待重连。
入口优先使用已有交付Python环境，缺少重连依赖时记录失败原因，不输出未核实的成功。
不能启动另一个看板进程冒充成功。报告保存配置摘要，未提供`--config-id`时不代签配置内容已加载。

现场冒烟运行
`./scripts/smoke-plugin --receipt /tmp/plugin-proof.json --session-id EXPLICIT_TEST_SESSION_UUID --output /tmp/plugin-smoke`。
它再次调用生效检查，对实际服务页面执行筛选、取消、空白原因、备注清空和真实等待反馈。
仅操作明确指定的本机卡片，逐次核对服务身份与版本，结束后用服务原有版本保护恢复人工状态和备注。
发现并发修改时拒绝覆盖，报告恢复错误；不会回滚数据库、版本或历史记录。
每次写入前保存恢复记录，保留截图和原始错误，核验全部原备注及配置，清理本次独立浏览器。
默认要求关闭标题、分区同步及自动归档；其他模式应在隔离环境安排专门验收。
此入口记录的是实际HTTP页面，不冒充原生插件容器内的指针拖动或完整31条验收。
每次使用新的源码外报告目录。三个CLI均记录实际耗时，原失败材料不覆盖。

开发提交运行 `./scripts/check --pre-commit`；PR 运行
`./scripts/validate --scope pr --base origin/main --output /tmp/pr-result`。
协调者将固定的原 PR 依次合并到 `codex/integration-*` 分支，解决冲突并审阅最终组合，
运行 `./scripts/check --prepare-release`，提交后推送候选分支。

候选工作流在 Linux 与 macOS 分别运行完整门禁，保存绑定当前提交和平台的记录，
打包并读回同一不可变 Release，最后确认 `Candidate gate` 成功。
每个平台只执行一次完整 automated 范围回归，要求退出 0、全部自动项通过。
报告保留真实环境待验项目和 `release_ready=false`，不代签完整验收；稳定发布仍被拒绝。
随后从 Release 读回实际包，使用既有原生 fixture、私有目录和随机回环端口，
检查包内启动器的 MCP 握手、界面资源、HTTP 服务身份及依赖就绪，关闭本次全部进程。
失败、跳过、身份错误、清理失败或报告与退出码不一致均拒绝候选。
缓存只复用依赖和编译产物，不复用其他源码的成功记录。
失败重跑使用 Actions 的失败任务重试及已有 Release 包，不重建已确认的平台包。
主线推送不再次触发整套构建；主线只接收已验证候选的同一提交。

仅更新 `context/` 内普通 Markdown、JSON 和 YAML 记录时，允许记录专用门禁。
工作流先确认主线为祖先，全部非记录文件的 Git 树与主线完全相同，
再确认该主线头具有 Actions 的成功 `Candidate gate`，执行项目检查与上下文检查。
该路径保留当前不可变插件包的原始源码身份，不升版、不构建、不重新发布。
任何代码、测试、检查器、工作流、版本或其他路径变化均走原完整双平台候选门禁。
汇总门禁要求分类及所选验证路径实际成功，路径失败或意外跳过均阻止主线更新。
记录同步须正常快进，推送前再次确认主线仍为检查报告中的基线。

协调者在候选的干净检出中执行：

```bash
./scripts/promote --candidate CANDIDATE_SHA --base EXPECTED_MAIN_SHA \
  --run ACTIONS_RUN_ID --repository OWNER/REPO --output /tmp/promotion.json
```

入口检查正确仓库和工作流、四项任务各自成功、双平台源码身份、报告和日志摘要，
核对双平台包启动报告，再次核对主线未前进，然后正常快进推送并读回确认。
不允许强推或用跳过状态提升。
GitHub 默认使用已有 `gh` 登录；自动环境可用 `CODEX_GITHUB_COMMAND` 指定参数数组形式的
既有凭据入口，不在脚本或记录内存放令牌。

服务端主线保护要求 `Candidate gate` 成功、分支为最新，并禁止强推及删除。
仓库权限不足以配置时必须明确报告保护未生效，不能把本地脚本等同服务端保护。
合并计时从开始处理固定 PR 头，到主线确认同一候选且上述不可变包可用为止。
调查、规则开发和计时结束后的记录收尾分别列出，不混入合并时间。
以后部署使用候选渠道中同一源码身份的包，客户端加载和功能验收单独计时。
