# 原生分区权威状态

## 日常状态与环境分区绑定

日常业务状态仍由 `model::board_states()` 定义。页面列、导航、编辑选项、排序和 MCP 枚举从该定义派生。
`Config::section_bindings()` 将有效状态与部署中的逻辑分区 ID 配对，账号匹配、目录验证、观察、移动和受管理分区判断共同使用它。
原生配置必须恰好绑定五个有效状态，各 ID 必须合法且互异；旧 completed 输入别名仍映射到待归档，但不增加原生依赖。
冻结六状态兼容模式、历史记录和旧标题前缀识别分别保留，执行协议的 completed 仍表示轮次正常结束。

旧六项原生配置通过显式命令写入新文件，源配置不变，已有目标拒绝覆盖：

```bash
bin/codex-session-board --config /path/to/old.json migrate-sections --output /path/to/new.json
bin/codex-session-board --config /path/to/new.json check-sections
```

迁移保留未知扩展字段及其余配置，按源目录解析 data_dir 后写成绝对路径，保持换目录后的数据位置。
迁移只发布配置，不打开数据库，不创建或删除客户端分区，不移列、不归档。已是五项时生成语义相同的新配置。
收据包含源文件 SHA256；它描述读取到的源快照，不锁住外部配置写者，部署前还需核对源未变化。
check-sections 只初始化原生读取连接并读取目录，不启动观察器或写入器。
预检通过仅证明当前时刻的账号、local 映射和目录，不保证后续 socket 或外部配置一直有效。
账号零匹配时报告最近候选缺少的状态，多匹配时明确报告数量；不按名称重新认领或取第一个账号。
正式切换前审阅自动归档资格，验收和切换期间关闭自动归档，避免修复读取后恢复执行积压归档。

独立有限模型位于 `src/formal/section_model.rs`，不从生产状态表生成期望值。
它对照真实配置校验、迁移、目录加载、移动、快照和 MCP 描述，检查 128 种键集合的 1,152 条编辑/迁移/重读边、
4,096 组账号与退役分区组合、120 种 UUID 绑定排列下的 600 次正确移动及 600 次过期拒绝，以及 30 类具体绑定/目录故障。
拒绝操作的写入记录必须为空，成功操作必须写入目标逻辑 ID；配置发布必须保留非退役字段。
模型是有限域的一致性验证，不证明外部原子 CAS、任意并发配置编辑或文件系统掉电持久性。
既有 1,077 状态、39,849 边的会话控制模型及冻结参考模型不变。
五种实现突变检出退役依赖复发、错误移动目标、迁移丢字段、额外绑定和漏验必需目录，不作为真实客户端操作验收的替代。
原生/远程发布汇总额外要求五项映射，以及同一候选二进制和配置的 check-sections 收据。

2026-11-07 用户授权将当前桌面 Codex 侧栏分区作为看板状态的唯一来源。
备注、人工确认锚点和新输入复核标记继续保存在本地。
SQLite 中的分区状态只作最后确认快照，不用于后台纠正原生位置。

## 接口选择证据

当前桌面工具的 `list_threads.sections` 与 `move_thread_to_sidebar_section`
是实际显示给用户的分区表面。仍使用既有 UI 分区 ID 和客户端会话别名映射。
原生 app-server 的 `threadSection/list` 和 `thread/section/move` 虽然可用，
却使用另一套 ID。对当前会话的可恢复测试显示，app-server 写入和读回成功后，
桌面侧栏位置未变，不能作为当前用户界面的权威来源。
测试前后原生记录保存在 `outputs/native-authority-20261107/probe-*.json`；
旧服务在测试后已恢复。

## 并发保证边界

桌面工具没有分区修订号或条件写。看板保存和归档必须携带读取时的原生位置，
执行前重新读取，移列后读回。发现外部位置变化时拒绝旧操作。
这些检查无法消除“检查后、执行前”另一客户端操作的窗口，
也不能识别两次读取之间已返回原位的外部操作，不宣称服务端原子 CAS。
丢回执或读回失败必须报告未确认，不能用本地成功记录驱动后台重放。

冻结的 31 条基础契约与模型保持不变。新权威模式需要独立覆盖外部移列、
直接保存、自动阶段去重、故障回执和归档原生资格；原本地兼容模式的
通过不等于新模式完成验收。部署证据必须绑定实际版本。

自动阶段更新只作用于已配置的状态分区和默认未分区区域。
Pinned 和未配置的自定义分区保留位置，不根据推测移走。
失败阶段只在原生位置未变时重试；一旦读到外部新位置或成功人工确认，
消费该阶段，不将旧期望回写。不同会话的失败不阻止后续会话推进。
迟到的读取快照不能覆盖本进程已经确认的原生写入。

原生位置改变的本地确认时刻用于挡住早于该确认的迟到终态事件。
终态缺少完成时间时也保留已经确认的原生位置，不假定它发生在用户选择之后。
真正的新执行阶段仍直接更新原生位置；同阶段重复扫描、启动历史和失败旧阶段
不会纠正用户的新选择。自动阶段完成后仍保留人工确认锚点，后续用户输入继续提示复核。
首次接入原生快照只建立缓存，不给全部历史会话新增标题任务。
归档原生读写在数据库锁外执行，不阻塞其他会话的备注和移列。
编辑提交失败时在当前浏览器会话保存备注草稿；重新打开用最新状态搭配草稿，
不重放失败的状态选择。无法使用浏览器存储时保留编辑框并明确提示。
原生分区没有输入确认版本。外部移入待归档且没有本地人工确认锚点时，
需要先确认一次当前输入，避免输入轮询先于分区轮询而把新消息当作已经复核。

旧的 11 个分区对账测试随用户撤销“本地状态获胜”的语义退休，
不再用重启纠正、先落本地后补偿或历史建议回写作为验收目标。
保护性断言迁移到 `native_authority`：身份与别名、独立读回和丢回执、
过期保存与归档、新输入、失败隔离、不阻塞其他会话、保留备注及重启。
原生 API 测试和实际二进制 HTTP/MCP 测试均进入原需求编号的测试绑定。
冻结需求、独立模型和锁未改动，不以兼容模式测试代替新路径证据。

## 客户端中断后的连接恢复

配置中的 `sidebar_socket` 是首选连接，不将 UUID 文件名视为永久存活的服务。
首选地址不存在或拒绝连接时，在同一目录重新发现实际可连接的 socket，
忽略已退出服务留下的文件。每个端点重新核验所有者、权限和对端用户身份，
只选择唯一存活端点。首选地址仍可连接时保持使用它；多个替代端点同时存活、
权限异常、连接超时或其他未确认错误时停止本次操作并显示异常，不猜测目标。
整个发现过程共用原有 RPC 超时预算，不按候选数量累加等待。

Linux 客户端升级可能将工具目录从 `codex-app-tools` 改为
`codex-app-tools-当前UID`。当配置地址属于这两种标准目录之一且已失效时，
在同一上级目录内检查这两个目录，允许旧目录已被删除，也支持回退旧客户端。
跨目录仍只接受唯一存活端点，不扫描其他 UID 或扩大自定义目录的搜索范围。
目录必须由当前用户拥有、不可被其他用户写入且不是符号链接；
socket 及对端身份继续独立校验。有效的配置地址始终优先。

恢复连接不会修改配置、清理其他进程的 socket 或发送状态写入。
已经发出的写入断连时不在传输层自动重放，仍由原生位置读回确认；
自动阶段失败后由观察器重试，每次重新核对原生位置。外部位置改变或人工确认
后消费旧阶段，防止连接恢复时把用户后来的选择移回去。
客户端尚未恢复时保留原有卡片与备注，健康信息报告待重试。

已经接受但尚未确认的阶段保存在 `runtime_pending_key`，看板服务重启后继续处理，
不把它重新归类为首次接入的历史。普通历史失败保护保持生效；
原生位置变化或成功人工确认会清除旧 pending，重启也不能恢复已被替代的阶段。
原生位置仍未改变时，同轮已经推进的新阶段可以替代旧 pending，
避免断连期间从运行转成失败后，重启只保留旧运行阶段或把新失败当成历史丢弃。

自动移动的回执和立即读回均丢失时，下一阶段处理前先读回旧 pending 的位置。
读到持久化目标状态表示该阶段目标已满足，记录自动确认，不将恢复时刻记成人工选择。
这样断连期间已经结束的轮次仍可继续进入待审阅；读到其他位置则保留外部选择。
后台位置刷新和运行扫描采用相同规则，顺序不同不会改变这一判定。
接口仍没有位置修订号，无法区分自动结果与恰好相同目标的外部操作；
这个已有的同位置操作边界不构成原子条件写保证。

`version` 是本地行计数，用来发现这次本地编辑已经过期。`input_revision` 是本地输入计数。`native_section` 保存上次读到的分区标识，不是侧栏修订号。旧库里的 `native_revision` 在打开时改成这个名字。同一分区移走再移回，这三列都认不出来。

活动列表完整、会话却只出现在原生归档列表里时，不算未读回的位置，本地行保持原样，不改列，也不替用户归档。活动列表重新出现已确认归档的会话时，恢复卡片并保留备注。这次读回不写 `native_choice_at`。
