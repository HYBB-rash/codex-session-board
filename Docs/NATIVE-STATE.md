## 并发保证边界

桌面工具没有分区修订号或条件写。看板保存和归档必须携带读取时的原生位置，
执行前重新读取，移列后读回。发现外部位置变化时拒绝旧操作。
这些检查无法消除“检查后、执行前”另一客户端操作的窗口，
也不能识别两次读取之间已返回原位的外部操作，不宣称服务端原子 CAS。
丢回执或读回失败必须报告未确认，不能用本地成功记录驱动后台重放。

冻结的 31 条基础契约与模型保持不变。新权威模式需要独立覆盖外部移列、
直接保存、自动阶段去重、故障回执和归档原生资格；原本地兼容模式的
通过不等于新模式完成验收。部署证据必须绑定实际版本。

自动阶段更新只作用于已配置的状态分区和默认未分区区域。
Pinned 和未配置的自定义分区保留位置，不根据推测移走。
失败阶段只在原生位置未变时重试；一旦读到外部新位置或成功人工确认，
消费该阶段，不将旧期望回写。不同会话的失败不阻止后续会话推进。
迟到的读取快照不能覆盖本进程已经确认的原生写入。

原生位置改变的本地确认时刻用于挡住早于该确认的迟到终态事件。
终态缺少完成时间时也保留已经确认的原生位置，不假定它发生在用户选择之后。
真正的新执行阶段仍直接更新原生位置；同阶段重复扫描、启动历史和失败旧阶段
不会纠正用户的新选择。自动阶段完成后仍保留人工确认锚点，后续用户输入继续提示复核。
首次接入原生快照只建立缓存，不给全部历史会话新增标题任务。
归档原生读写在数据库锁外执行，不阻塞其他会话的备注和移列。
编辑提交失败时在当前浏览器会话保存备注草稿；重新打开用最新状态搭配草稿，
不重放失败的状态选择。无法使用浏览器存储时保留编辑框并明确提示。
原生分区没有输入确认版本。外部移入待归档且没有本地人工确认锚点时，
需要先确认一次当前输入，避免输入轮询先于分区轮询而把新消息当作已经复核。

旧的 11 个分区对账测试随用户撤销“本地状态获胜”的语义退休，
不再用重启纠正、先落本地后补偿或历史建议回写作为验收目标。
保护性断言迁移到 `native_authority`：身份与别名、独立读回和丢回执、
过期保存与归档、新输入、失败隔离、不阻塞其他会话、保留备注及重启。
原生 API 测试和实际二进制 HTTP/MCP 测试均进入原需求编号的测试绑定。
