# 插件运行时的所有权

正常安装只有桌面插件入口。安装器负责取得、校验和安装程序包，再请求正在运行的桌面客户端重载插件。
配置选择、数据库备份、业务线程与 HTTP 监听由 Rust 运行时统一持有。

## 配置入口

`RuntimeHandle::load` 只读取一次配置，后续请求使用这份已解析配置。
安装器不接受 `--config`，也不根据端口、文件名或数据库修改时间选择数据。
正式入口默认使用 XDG 配置目录中的 `config.json`；独立实验可以显式指定配置。

首次升级时，运行时只采用安装回执明确记录的旧正式配置。
这段兼容逻辑在配置锁内执行，并写入一次性迁移记录。
回执指向的文件缺失会返回错误，不会改用旧插件缓存或创建空数据库。
后续升级沿用同一入口，避免安装脚本与业务程序分别决定配置。

## 运行时与退出

每个 MCP 进程都有一个 `RuntimeHandle`。配置入口锁和数据目录锁决定唯一所有者。
所有者持有 `RunningBoard`，直接调用 `App`；其他入口验证现有实例后转发请求。
跟随入口每次请求重新确认所有权，原所有者退出后可以接管。
同一入口即使修改了 `data_dir`，旧所有者仍持锁时也不会再开一份实例。

`RunningBoard` 持有监听器、应用和锁。`App` 持有它创建的观察、归档和请求工作线程。
退出先关闭新操作和线程登记，发出取消，再等待现有操作、远程实例及线程退出，最后释放监听器和锁。
远程实例替换也必须先等待旧实例退出，不能留下继续写数据的旧观察线程。
周期等待可被取消，不会等完整轮询间隔才退出。

HTTP 用于网页和其他 MCP 入口访问同一应用。它是插件内部线程，随持有者退出。
手工运行 `serve` 仍用于明确的独立部署；普通安装和更新不会创建分离的 `serve` 子进程。

## 数据与安装回执

新构建打开业务数据库前，运行时通过 SQLite backup API 保存主库和远程缓存库。
备份包含已提交 WAL、实际配置与构建身份，不复制私钥。
同一配置与构建重复启动复用已完成备份；失败的临时备份不会成为完成记录。
程序包不携带实际配置或数据，历史数据目录即使在旧 release 内也必须保留。

安装回执区分程序包已安装和当前客户端已加载。重载使用 `CODEX_THREAD_ID` 确认该会话已在所选控制 socket 的宿主中加载。
只有同一会话的 MCP 连接确认版本、插件 ID 与工具，并成功读取 `board_snapshot`，才记录已加载。
没有会话上下文或会话未在该宿主加载时，保留 `awaiting_desktop_reload`；不使用无会话的临时发现清单代签当前客户端。
桌面未运行时保留等待重载状态；不得用临时 CLI 服务的成功代替桌面加载成功。

## 验证边界

进程集成测试覆盖并发入口、共享所有者、退出接管、受保护写入和旧配置迁移。
线程测试覆盖关闭登记、并发退出、旧远程实例回收和失败重试。
这些测试不替代冻结的 31 条需求及目标环境验收；缺少真实环境证据时仍保持待验证。
