## 不能直接交付通用功能的限制

`create_project` 的包装层先核对 sources 是否在调用会话授权的 workspaceRoots 内，
随后才进入原生项目服务及信任确认。当前会话的本机根只有本仓库；
日常部署配置中既有 sidebar caller 的本机根列表为空。
前者只能登记仓库内的目录，后者不能加入任意已有目录。
不能更换 caller、伪造 host 或构造符号链接绕过这一检查。

不传 sources 会让原生服务自动选择默认工作目录，并可能按照客户端设置初始化 Git。
这无法兑现用户选择父目录、加入已有目录和默认不初始化 Git 的方案。
路径深链则可能打开新建页、改变全局选择，也没有独立创建事务回执。
直接调用 app-server project/create 不能完成 Desktop 登记及 ID 映射。

客户端内部 appServices.projects 已通过 renderer RPC 暴露 createLocal，
但这条 Electron IPC/MessagePort 通道没有已核实的外部调用入口。
要支持通用本机路径，需要新增窄客户端 bridge，扩展桌面客户端安装包并重启。
本轮尚未实现或部署此扩展，业务功能也尚未实现。

## 待确认的最小客户端扩展

扩展作为客户端可选功能维护，不把看板路径、会话 ID 或部署端口写进客户端源码。
只开放当前用户私有 Unix socket，校验目录所有者、权限和既有端点身份。
禁止 TCP、任意脚本、任意 app-server 方法及 caller/host 切换。

只需要以下操作：

| 操作 | 契约 |
| --- | --- |
| list | 返回原生本机项目 ID、名称和完整根目录，不返回聊天内容。 |
| pickDirectory | 复用原生目录选择器，支持取消，不登记项目或创建会话。 |
| register | 接受名称、一个已存在的绝对目录及请求 ID，复用原生 createLocal 和信任确认；强制 setActive=false，不初始化 Git。 |

register 在客户端串行核对真实路径。相同根目录返回已有 Desktop ID；
同名不同目录允许。原生确认取消如实返回取消，未经确认不扩大目录访问。
丢回执先按请求和路径读回，不在注册结果不确定时自动重发。
不直接编辑 local-projects、project-order 或 ID 映射。

看板侧新增两个入口，共用受保护的 HTTP/MCP 操作和项目结果处理。
新建目录使用排他创建；加入已有目录不改内容。目录创建成功而登记失败时保留目录，
显示阶段并支持继续登记。创建中的跨标签页重复请求由后端及客户端共同协调。
项目表单打开时暂停重绘并作废在途旧快照；成功读回目录后切换到新项目。
嵌套项目会改变按 cwd 计算的旧会话归属，需要在提交前提示，状态和备注保持独立。

专项验证覆盖确认、取消、超时后完成、重复路径、符号链接、并发、
中文路径、权限失败、零会话项目、嵌套项目和 HTTP/PWA/MCP 入口。
冻结的 31 条契约、参考模型和锁保持不变，完整门禁缺证继续保留待验证。
