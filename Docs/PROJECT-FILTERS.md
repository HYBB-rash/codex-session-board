# 项目筛选与搜索

顶部先选择主机，再选择该主机的项目或搜索。每次打开页面默认选择“本机”，展示本机会话。
手动选择“全部主机”可查看总览，此时项目框提示先选择主机。
主机来自登记、项目、会话缓存及连接快照，空主机仍可选择。
切换主机重置为该主机的全部项目，搜索文字保留。搜索覆盖当前主机的全部项目，
不受隐藏的项目选择限制；全部主机下搜索才是全局搜索。筛选只保留在当前页面。
计数、状态导航和列内归档都使用当前筛选结果，五列或兼容六列始终保留。
离线主机可以查看已有缓存；选择主机不发起连接。没有缓存时提示尚未读取。

在项目选择模式中选中具体项目后，点击“新建会话”会把该项目带入原生新建页。
远程主机在搜索、全部项目或默认工作区下，先选择该主机的已登记项目；
没有项目时提示去对应客户端登记，不能落回本机。全部主机总览下先选择主机和位置，
本机的全部项目、默认工作区或搜索继续打开本机输入页。新建请求固定使用点击时的项目 ID；
后端重新读取登记表，项目已经移除或登记表不可读时提示错误，不退回其他项目。
新建页仍由原生客户端处理工作树、分支等设置，看板不发送消息。

## 项目来源与刷新

只读当前 Codex 客户端全局状态的 `local-projects` 与 `project-order`。
优先使用配置的 `sidebar_state_file`，否则读取
`$CODEX_HOME/.codex-global-state.json`，未设置 `CODEX_HOME` 时使用
`$HOME/.codex/.codex-global-state.json`。这个配置与分区同步共用，但项目筛选
不要求启用分区同步，也不改写客户端的项目或会话。

读取完整登记表后才替换目录；文件缺失、损坏或格式不符保留上次完整结果，
并显示项目列表暂不可读。首次读取失败时项目框不可选，仍可查看全部与搜索。
完整登记表明确为空才表示没有加载项目。远程项目不进入本机列表。
项目工作线程按 `runtime_poll_seconds` 读取，页面每四秒刷新。
编辑、新建选择与新建结果核对期间暂停页面替换。普通拖动等待保存时，
仍可切换主机、项目、搜索或打开其他会话；正在移动的卡片不可打开。
临时落位只用于显示，已确认记录和新快照在保存结束后更新。
归档、排序、新建和重复保存继续禁用，编辑表单保存时保持输入与取消保护。
新建结果不明确时保留原主机、项目及请求 ID，资料变化不产生新的创建目标。

这是当前桌面客户端的内部文件格式，并非公开稳定 API；客户端升级后若改变格式，
程序会报错并保留已有分类，需要重新核实来源。原生 `list_projects` 会省略
Git 探测失败的项目，而且只返回多根项目的首个目录，因此没有把它作为完整登记表。

## 会话归属

- 按会话工作目录匹配项目的全部根目录，不依赖可为空的原生 `projectId`。
- 路径按目录组件匹配，嵌套项目取最长根目录；同名前缀的旁边目录不会误匹配。
- 解析已有目录的符号链接；目录暂时不存在时，保留可解析父目录与剩余路径。
- 普通路径无法匹配时，只读 Git 的 `.git`、`gitdir:` 与 `commondir`，
  按共享 Git 目录识别外部工作树，并保持子项目相对目录限制。
- 同一共享 Git 目录对应多个同等优先级项目时不猜测归属。
  Git 元数据异常时保留仍有效的上次分类；没有可靠分类的会话在全部与搜索中可见，
  卡片显示“项目归属待确认”，不会被当作已确认的默认工作区会话。
- 完整目录中重复的规范化根目录导致整轮刷新失败，避免任意选择项目。
- 同名项目在下拉选项附加目录，零会话项目仍可选择。

未匹配且没有读取异常的会话属于默认工作区。归属由当前登记表动态计算，
不修改 SQLite 中的人工状态、备注或版本。移除项目后归默认，重新添加同一目录
即使项目 ID、名称改变也能识别。移除当前选中项目时页面切至当前主机的全部项目并提示；
重新添加后会话自动回项目，页面保持当前筛选，避免突然跳转。

## 连接与异常提示

顶部先说明当前主机受影响的功能，其他异常主机显示数量摘要。详情分别说明会话读取、
自动状态、状态分组与修改权限，提供成功读取时间、处理办法和可展开的原始诊断。
主动关闭连接的主机不算故障，旧的连接标记不能证明在线或可写；未知错误不猜测根因。
后台定时归档继续按原配置运行，页面筛选不影响它。批量归档显示数量并固定点击时目标。
项目读取失败保留原选择；其他主机的缓存提示不阻止已确认项目移除后的回退。
主机移除后保留原范围与明确提示，不自动扩大为全部主机。
