# 可靠性改进实施方案

日期：2026-11-14。调查基线：`966795746becd982ec1bdf1d2e6df735c369601e`。
本文件是待实施方案；隔离副本中的原型不等于产品已实现、已合并或已验收。
实验索引：`context/results/reliability-plan-20261114.md`。

## 目标与取舍

让常规业务实现只处理业务意图，让一次验证自动完成环境准备、用例选择、运行、清理和结果解释。
优先级固定为：语言和模块边界消除错误调用，其次自动检查，最后才是审阅约定。
第一轮不换测试框架，不增加运行时依赖，不修改数据库格式，不改变现有业务规则或发布授权。
继续使用 `scripts/validate`、`rust_adapter.py`、现有浏览器工具、开发 fixture、打包和验收器。
不引入 Nextest、Playwright 迁移或通用变异测试平台；当前缺口在这些工具之间的环境和证据衔接。

前次连接改动修正了正常路径的端点继承、归属检查和重连行为。
本轮发现的剩余缺口是：同一 crate 的业务模块仍可调用原始构造器。
因此下一步补编译边界，保留已经正确的运行时归属校验。

## 已通过实验确定的方向

| 问题 | 实验及决定 |
| --- | --- |
| 原始连接是否能收口 | 原实现允许别名、空格变体等5种调用；原型的6种绕过或伪造凭证调用均被编译器拒绝。采用私有字段凭证，不用兄弟模块间无效的 `pub(in ...)` 限制。 |
| 测试是否迫使生产入口公开 | 集成测试走 `App::connection`；fixture 的原始 socket/stdio 客户端移至示例和测试支持。全目标编译、原生及远端回归可继续运行。 |
| 状态重构是否需要换模型或迁移数据 | 不需要。SQL 写入选项留在 native 模块内部，事务入口调用业务操作；独立参考模型继续验证旧有行为。 |
| 错误提示能否与业务判断分开 | 可以。具体错误类型保留在 anyhow 链中；同文案的 I/O 故障不能成为业务拒绝。 |
| 前端能否先保持行为不变 | 512种状态、2560个旧新条件比较一致；143个现有浏览器场景通过。保留内嵌脚本和现有启动器。 |
| 环境是否真的需要统一 | 强制 Python 3.10 复现 `tomllib` 缺失；同一个测试二进制在 macOS 临时路径别名下失败、规范路径下通过。复用已有适配器的规范路径设置。 |
| 只用 finally 清理是否足够 | 不够。诱发运行者 SIGKILL 后旧方式剩3个进程；归属管道原型在正常、失败、超时、SIGINT、SIGKILL五种场景清空自己的进程组，未动旁路进程。 |
| 打包是否需要重写 | 不需要。实际加入一个未被打包规则覆盖的无扩展名入口，现有预检在约0.7秒内拒绝。把它前置并补清晰诊断。 |
| 可以立即并行提速吗 | 不采用。一次既有1000毫秒断言实测1018.55毫秒失败；诊断复跑通过不能消除首轮失败。先采集分段耗时，时间敏感测试串行。 |
| 编译缓存可以跨副本共用吗 | 本轮共享 target 曾错误复用另一副本产物；相同内容只刷新时间戳便由通过变成预期编译失败。改用每个源码副本独立 target，并重新验证。 |

这些实验确定实施方向，没有证明原型已经符合完整候选门禁。正式修改仍须通过格式、Clippy、完整组合和双平台检查。
实验中的失败、错误筛选和缓存误用保留原始记录；不得用最后一次成功覆盖它们。

## 1. 统一验证入口

扩展 `./scripts/validate`，保留现有 `pr`、`candidate`、`preflight`、`--staged` 语义及默认 candidate。
新增 `--scope task`、`--plan`、`--report RUN_DIR`；不另造一个与其竞争的验证入口。
`task` 用于未提交工作，明确不能作为主线提升凭据；`pr` 和 `candidate` 继续要求干净的提交。
`--plan` 只展示解析后的环境、改动和步骤；`--report` 只读已有报告，不重跑或安装任何东西。
task 默认创建源码外的唯一私有结果目录；现有 `--output` 用法继续可用。

### 环境和源码

- 先创建失败也能落盘的运行记录，再解析工具；解析失败必须有状态和可执行的纠正提示。
- 选定一个支持 `tomllib` 的 Python 3.11+；优先显式配置，其次当前 PATH 和已有项目环境中的可用解释器。没有合适版本就退出，不自行安装。
- 子进程统一继承选定解释器、规范临时目录、测试配置和已核对的工具路径；不修改用户全局 PATH。
- macOS 使用现有适配器的 `/private/tmp` 规则；记录操作系统、架构、工具版本和绝对路径。
- 临时源码副本、独立工作树分别使用自己的 Cargo target；拒绝把一个已归属其他副本的缓存直接当成本任务缓存。
- 保留现有暂存快照机制；暂存检查与工作区检查分别记录身份，不能用未暂存修复证明暂存代码通过。
- task 身份包含 HEAD、已跟踪差异摘要、未跟踪实现文件摘要、实现指纹；运行前后身份不一致即失败。
- PR/candidate 保留提交、树、实现指纹和平台绑定。新增报告不得放进源码或改变实现指纹。

### 选择与执行

把现有 `related_commands` 改成可测试的路径到验证集合的映射，覆盖提交差异和 task 的本地变更。
保留源码→Rust业务回归、界面→UI、检查器→检查器/钩子、Python→对应验收工具测试的现有关系。
明确列出的纯文档/上下文改动可只检查相应规则；未识别的实现路径回退完整自动验证，不默默跳过。
task 运行相关静态检查、测试及源码包预检；提交规模、干净工作区和发布版本仍由现有提交/候选门禁负责。
候选继续运行完整自动验收。真实目标证据通过既有 `verify_acceptance.py --evidence ...` 核验，不能用 fixture 替代。

复用 `rust_adapter.py` 的测试发现和绑定校验，先保存实际测试全集、计划集合，再执行。
完成后逐项核对预期 ID、执行 ID、结果及数量。零测试、只跑到部分前缀、重复、缺失或 skip 均不得冒充完成。
单一 DAG 内只执行一次相同检查；复用编译缓存，不跨源码指纹复用“测试通过”结论。
第一版维持现有串行测试策略；浏览器、真实时间阈值及进程测试不相互并发。
不自动重试至通过；诊断复跑属于同一失败记录的后续证据。

### 报告和兼容

沿用 `VALIDATION.json`，将新编排报告升到 schema 2；不改 `automated.json` 的验收权威。
保留候选原有三个 `steps` 的含义和顺序；准备及清理放在独立字段。
同一 PR 更新 `promote_candidate.py` 和测试，核对新增阶段、日志摘要及最终清理结果。
旧报告只作为历史读取；新编排生成的新候选必须提供完整 schema 2，不通过缺字段默认值放行。

报告必须包含：源码身份、工具环境、选中用例、逐项结果、步骤耗时、日志摘要、
首次失败、诊断重跑、资源归属/清理、待验证项，以及适用时的目标和产物身份。
终端摘要固定显示“本范围结果、失败原因、待验证项、报告位置”；不只输出 exit 0。
`scope_passed`、`release_ready`、目标验收状态独立。自动范围通过可以仍有真实环境待验证。
退出码：0本范围通过；1断言/规则失败；2本次请求范围缺必需外部证据；3环境或工具错误；130中断。
仅外部验收缺证据时，不让自动 PR/candidate 冒充失败或完整验收成功。
已发生失败不能被后续 pending 掩盖；异常退出和清理失败也不能产生通过报告。

## 2. 连接边界

修改范围：`src/app.rs`、`src/app/connection.rs`、`src/preflight.rs`、`src/rpc.rs`、`src/rpc/framing.rs`、相关集成测试及 fixture 支持。
`App::connection` 是业务、观察器和集成测试的有归属入口，继续核对启用状态和操作角色。
`DesktopConnection::configured` 只接收 `app::connection` 模块私有字段的 `ConnectionRequest`，不接受裸 Config。
凭证只在 connection 模块及其预检子模块构造；app 其他业务子模块与外部模块一样，不能伪造 tuple 字段。
将 preflight 的模块归属放到 connection 下，通过 re-export 保持调用路径；不为了预检创建 App 或数据库。
原始 connect/proxy 不暴露在生产构建中，remote 只对 rpc 内部可见。
fixture 的低层 socket/stdio 客户端独立于生产模块，不增加可误启用的生产 test feature。
`StdioReader` 的历史补读和 CLI 历史诊断用途保留；不得借本次重构把它变成实时服务。

门禁使用真实 crate 的外部业务模块及 app 业务子模块编译反例，包括别名、空格、裸配置、remote/proxy、伪造凭证，共六种形式、十二处拒绝位置。
先证明正向样例可编译，再确认每个反例在指定位置、以指定诊断类别失败；其他编译故障不算拦截成功。
夹具在源码外隔离副本注入，不改工作树。Rust 隐私约束负责禁止调用，现有词法检查只辅助提示。
验收保留全目标编译、5个归属测试、36个 native_authority 测试、2个重复远端来源测试及 fixture 历史协议。

## 3. 状态操作与错误

修改范围：`src/store.rs`、`src/store/native.rs`、`src/store/runtime_native.rs`、`src/store/drafts.rs`、
新增错误类型模块、HTTP错误序列化和相关测试。
现有 Store 公共操作继续拥有事务与版本检查，业务调用者不得自行拼 SQL 写入标志。
将 `DailyWrite`、Pending/Choice/Phase 等实现细节私有化；不只是给原旗标结构换名字。

| 业务操作 | 必须在入口保留的条件和原子更新 |
| --- | --- |
| 确认人工选择 | 状态版本、输入版本、已确认原生位置、备注限制；在同一事务中写入人工选择依据及版本。 |
| 确认自动阶段 | 会话未归档、状态版本、pending key、原生结果与预期一致；消费 pending 和阶段写回不可拆开。 |
| 确认归档 | 输入版本、待核对状态、待归档列；状态和对应待处理记录按现有事务同时收尾。 |
| 恢复原生可见会话 | 使用已确认的原生观察及原有版本约束；不能因一次扫描缺失就推断归档或恢复。 |
| 保留/排队/消费阶段 | 用不同内部函数表达，不允许调用者自由组合 archive/unarchive/clear/bump 等开关。 |

远程 RPC 仍在 SQLite 事务之外，通过既有前后读回和版本比较确认；不宣称实现分布式原子事务。
丢失回执保留不确定状态，核对后再决定；不得自动向另一个后台重放写入。
保留旧模式 `preserve_runtime` 与 native `old_event_keeps_card` 的语义差异，不为“统一”而合并。

错误分类固定为业务拒绝、输入拒绝、技术故障。anyhow 继续承担传播和上下文，不更换错误框架。
业务类型覆盖状态/输入冲突、已归档、位置未确认、归档待核对/列不符、过期自动阶段及原生确认不匹配。
草稿错误覆盖请求不存在、已结束、跨项目复用、会话身份不符及已有待核对请求，携带必要身份数据。
未知状态、备注超限和非法输入属于输入拒绝；数据库、网络、JSON解析异常保留技术原因。
按根错误的具体类型分类，不按文案或错误链长度；不能给 I/O 错误套业务 context 后把它签收为预期拒绝。
HTTP 增加稳定的 `errorCode`，保留现有 `error` 文案及状态码，避免把行为重构夹带为协议变更。

`formal/check.rs` 比较预期类型和参数，继续断言被拒绝操作没有改变任何持久状态。
参考模型独立计算预期；不得导入生产转换函数、生产写入助手或用成功/失败布尔值替代原断言。
保留31条需求、模型、锁和原覆盖规模；新增测试绑定到已有需求，不降低或替换原断言。
编译反例必须证明 store 的其他模块不能构造同时 archive/unarchive 的写入对象。
测试要覆盖中文文案变化、增加 context、同文案技术故障、陈旧状态/输入版本和事务拒绝后的数据不变。

## 4. 前端操作规则

修改 `index.html` 和现有浏览器测试，不引入模块加载、打包器或另一套浏览器测试框架。
一个纯函数计算操作权限；输入是交互快照和相关会话事实，输出固定的能力集合。
全局能力至少覆盖 mutation、independent、filter、render、load、drag、open、cancelEditor。
卡片能力在同一处叠加 readOnly、位置/pending、目标卡片身份；不在各按钮复制第二套规则。
保留交互的独立维度，不强行把编辑、创建、拖动、待确认移动压成一个互斥状态枚举。
按钮禁用、拖动入口、表单提交、筛选、打开、加载结果接收和写请求入口都消费这份权限。
原始写请求收进业务动作入口，使新按钮调用业务动作时也自动经过权限判断。
保留 requestSerial、防陈旧响应、取消编辑、未知移动结果恢复、动画及减少动态效果行为。
主机/项目筛选只影响视图；不能变成重新选择后台或更改后台连接。

验收以冻结源码的条件矩阵保持等价，再执行现有真实浏览器场景。
矩阵证明旧新等价，不证明旧需求正确；需求和独立浏览器断言仍是验收依据。
新增按钮必须经过共用动作入口，禁止以给每个按钮补相同 if 作为完成标准。

## 5. 通用验证资源与可重放故障

复用 `scripts/dev_environment/processes.py`、`browser-client.mjs`、`browser-actions.mjs` 及现有 fixture。
统一租约记录：任务 ID、源码身份、私有配置/目录、端口、PID/启动身份、进程组和清理结果。
归属管道连接实际任务运行者或 dev supervisor；一次性 `dev start` 命令正常退出不应关闭长期 supervisor。
运行者死亡时守护进程收到 EOF，停止自己的子进程，写清理回执；不能只依赖运行者的 finally。
正常、异常、超时、SIGINT、SIGKILL都必须验收，旁路进程必须始终存活。
进程扫描排除扫描命令自身；五种场景既核对进程组为空，也核对清理回执，不能只凭守护者退出判定。
不按端口或进程名大范围清理；PID身份变化或归属无法证明时报告未清理，不猜测并杀进程。
守护者自身被强杀或系统断电不保证即时回执；下一次只读核对租约，未确认前不得报告清理完成。
统一入口负责启动 fixture、等待可用、运行浏览器、截图/日志归档和清理，默认不接触日用客户端。

把现有业务及 fixture 故障样例固化为命名重放集合，保留现有39+11样例作为起始清单。
固定源码和补丁前置条件；补丁未应用、编译失败、超时、预期断言失败分别报告。
只有目标原断言确实捕获预期错误才计入检出率，不把“工具没跑起来”算作发现业务缺陷。
沿用现有手动时钟与浏览器动画控制，不把 JS 假时钟当作 CSS/渲染时钟。
源码包预检前置到工具或入口变更验证；缺文件时列出源集合与包内集合差异。
保留当前打包白名单及独立解包指纹比较，不用无条件打包整个仓库替代。

## 6. 交付阶段记录

用带身份的事实记录代替单一“完成”状态，投影为已实现、已合并、已产包、已安装、客户端已加载、完整验收。
这些是独立维度：候选可以先产包；安装不能证明加载，加载不能证明完整验收。
新增任务通过工具生成 `context/results/<task-id>.json`，任务卡引用该记录。
记录 schema、任务 ID、来源提交/指纹、事实类型、产物哈希、适用目标、证据路径/哈希、时间和状态。
实现完成由明确范围和审阅记录声明；合并、产包、安装、加载由各自已有工具回执证明。
加载证据必须绑定实际目标、客户端/后台身份及产物；不能从版本文字或安装回执推断。
验收继续执行完整验收器，且证据内容经审阅；自动通过、HTTP 200 或 fixture 不能自动升级。
合并完成仍是最终组合自动门禁、主线更新、不可变插件包和隔离启动通过，不包含安装与真实客户端验收。

工具只导入可核对的回执，不把 Agent 填写的 `passed=true` 直接当成证明。
跨源码、跨产物、跨目标的证据拒绝用于当前完成判定；旧安装另行显示，不抹掉也不冒充当前候选。
老任务缺可靠证据时标记 legacy_unknown，不猜测回填；新任务不享受缺证据豁免。
更新 `validate_context.py`、任务模板和打包规则；协调者仍独占共享 STATE、注册和归档写入。
独立任务只写自己的记录；生成状态视图而不另维护一份可能矛盾的手写总表。

## 7. 可直接分派的 PR 顺序

每个 PR 独立工作树；开发提交仍遵守13文件/400行，不把 PR 等同一次提交。
前后依赖固定如下；不在实施途中自行改工具、放松阈值、改业务语义或部署日用插件。

| PR | 修改范围与交付 | 前置 | 关闭条件 |
| --- | --- | --- | --- |
| R1 验证基础 | validate、报告/环境/命令进程底座、promotion及工具测试 | 无 | 坏解释器、别名路径、错误缓存归属、初始化失败有明确失败报告；命令归属和退出可核对；旧入口兼容，新报告可验证。 |
| R2 连接边界 | app/rpc/preflight、fixture支持、编译反例 | 无，可与R1独立实施 | 6种反例在2个模块位置均拒绝；正向构建、归属/原生/远端及fixture回归保持通过；Clippy无警告。 |
| R3 单次任务验证 | 改动映射、测试清单、资源租约、浏览器/fixture编排、打包预检 | R1 | 干净环境只需一次入口；零/漏/跳过测试拒绝；5种退出清理且不伤旁路进程；未知实现改动不漏检。 |
| R4 业务错误类型 | store错误、HTTP编码、formal比较器、草稿错误及测试 | R1 | 原预期拒绝全部迁移到类型和参数；技术错误不得被签收；文案/context变化不影响分类。 |
| R5 状态业务入口 | store/native/runtime_native与调用点 | R2、R4 | 私有写入反例拒绝；原独立模型、版本竞态、重启/归档/丢回执回归全部通过，无数据库迁移。 |
| R6 前端权限 | index及浏览器用例 | R3 | 条件矩阵等价；所有动作入口共用规则；143个既有相关场景及新增拒绝路径通过，筛选不改变后台。 |
| R7 交付事实视图 | context工具/模板、回执适配、文档 | R1、R3 | 错来源/目标/产物和自动冒充完整验收被拒绝；旧记录未知不被补造；合并完成判定不含部署。 |
| R8 故障重放和指标 | 固定故障集合、分段耗时、汇总命令 | R2至R7 | 重放明确区分检出与工具故障；首轮结果保留；按同机同范围输出基线，不自动启用并行。 |

R3完成时做一次“新 Agent 接手”验收：只给任务卡及标准命令，自动得到环境、选择原因、结果和待验证项。
R2与R5的反例不直接改生产工作区，且正向编译先通过，避免错误被无关编译失败掩盖。
每个 PR 运行相关测试，最终组合仍执行完整候选门禁和不可变包检查；不因原型通过减免。
出现新技术阻断时保留失败并停止该 PR 的完成判定，不降断言、不自动换框架、不把待验证写成成功。
真实客户端验收另有明确目标和授权后执行；本方案不授予安装、重载、推送或部署权限。

## 8. 收益与观测

| 收益 | 用户可以查看的证据 | 第一轮标准 |
| --- | --- | --- |
| 少记连接与状态规则 | 编译反例、业务调用点不再出现裸构造器/写入旗标 | 固定反例全部被正确原因拒绝，合法入口仍通过。 |
| 少做重复验证准备 | 单次运行的环境、fixture、测试、打包、清理和报告 | 标准自动范围只需一次入口；缺环境直接指出缺什么。 |
| 更少“通过但没验证到” | 测试ID对账、源码/产物/目标身份、首次失败及pending | 零测试、部分筛选、过期证据、skip均不能签收。 |
| 更少状态和交互回归 | 独立模型、拒绝后的数据库快照、浏览器组合场景 | 保持覆盖规模和业务行为；新增操作只接业务入口。 |
| 看懂真实进度 | 同一任务的六个独立阶段、目标身份和缺失证据 | 明确停在合并、产包、安装、加载还是验收，不混写“完成”。 |
| 更少环境污染 | 归属租约、退出方式、清理回执及旁路控制 | 五种退出场景自己的残留为0，旁路进程不受影响。 |
| 找到真正的耗时 | 准备/构建/测试/产包/清理/报告的分段和总耗时 | 前10个可比任务记录首轮结果；按同机、同范围、冷暖缓存分别比较p50/p90。 |

同时统计每类失败在PR和最终候选出现的位置、首次通过率、诊断重跑次数、待人工补证据项。
不把未知的 Agent 思考时间或未记录的手动动作伪装成 CLI 可测数据。
当前不能承诺总验证时间下降某个百分比，也不能据此承诺看板点击更快。
最确定的收益是减少环境准备、漏验、错误完成判定和重复修复；测试本身的提速待同范围数据支持。

仍需人判断：业务语义是否正确、交互是否符合使用习惯、独立模型是否合理、真实证据是否足够、
跨功能取舍及正式发布时机。工具固定流程和证据门槛，不替人把这些判断自动标成通过。
