# 远程分区实时映射验证

## 结论

2026-11-14 在 Fedora 日用客户端上执行五次只读 `list_threads` 调用。
接口稳定返回五个逻辑状态分区及其成员，但没有返回
`hostSectionIds`，成员摘要也没有原生后台分区 ID。
因此，目前使用的这条实时接口不能直接提供完整的“逻辑分区 → 主机 → 后台分区”映射。
之前提出的“直接从实时接口获得完整映射，再确认远程位置”不能照原样实施。

返回的逻辑成员列表可以作为另一种方案的输入，但其主机归属、并发一致性和移动后的
确认语义仍需单独验证，不能在本次调查中宣称已替代原生位置确认。
两个真实空分区说明，单靠成员会话也无法完整还原五个分区的后台对应关系。

## 成员字段的额外限制

五个分区共有 16 个成员，其中一个明确登记为远程 Mac 会话：
`01a1b88f-70fd-73c1-b10b-10f856dfd5a6`。
该会话在客户端持久化 `threadHostIds` 中归属
`remote-ssh-codex-managed:f6cdae6b-9c38-4789-9071-db5e90f93a7c`，
实时成员键却是：

```text
codex:thread:local:01a1b88f-70fd-73c1-b10b-10f856dfd5a6
```

这里的 `local` 不能直接解释为物理主机。主机归属的这次交叉核对用了持久化数据，
不能据此声称该归属表已能从实时接口获得。
仓库 `src/native_sections.rs::collect` 按 `config.host_id` 拼成员前缀，
直接复用到这类真实远程响应时会漏掉该成员。
因此，改回逻辑成员接口不能只替换一个读取函数，还要验证会话别名和主机归属。

## 对方案的影响

1. 原方案所需的完整实时映射没有从现有工具接口取得，暂不恢复远程自动分区。
2. 只靠名字配对不能排除同名或重建分区；只靠成员也覆盖不了两个空分区。
3. 本次持久化文件里已经有五个状态分区的本机和远程映射，共十项。
   这为“初始化时校验既有映射，日常复用映射并读取原生位置”提供了下一轮实验条件。
   本轮没有验证后台目录、映射失效后的恢复或新主机初始化，不能把这个收窄方案写成已可交付。
4. 已有会话的批量整理应在确认机制验证后再执行；本次不改业务状态，
   不增加“待核对”列，也不根据不完整的成员结果将旧会话判为未分区。

## 证据与清理

原始回执在源码之外的 `/private/tmp/csb-live-mapping-20261114/`：

- `receipts.json`：五次真实工具结果，以及前后持久化分区读取。
- `archive-index.json`、`source-findings.json`：当前包版本、资源名、哈希和序列化片段。
- `native-tools-inventory.json`：对端进程和 `tools/list` 的实际错误响应。
- `summary.json`：字段、成员稳定性、空分区、远程成员、前后相等与清理断言。
- `probe.py`：本次只读探针。私钥通过 1Password 的 OpenSSH 格式读取，在内存中交给临时 agent。

全部五次响应的字段断言通过，前后五个持久化分区及其映射、成员完全相等。
两个成功实验进程组的 SSH 与临时 agent 均已退出，临时 agent socket 已不存在。
普通 SSH Agent 拒绝签名、直接导出密钥格式不兼容的尝试没有计入接口测量；
最终使用 OpenSSH 格式读取完成认证，私钥没有写入回执或临时文件。
