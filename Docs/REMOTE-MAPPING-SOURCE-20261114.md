# 远程分区映射的源码调查与校准实验

## 结论

有可落地的确认路径，不需要修改 Codex 桌面端，也不必等待映射文件保存。
已有映射可在连接时用原生分区目录校验后复用；缺失映射时，可以用一个专用空会话，
通过原生侧栏工具移动到指定逻辑分区，再把逻辑成员关系与后台实际分区 ID 交叉核对。
这能建立对应关系，不依赖分区名称唯一，也不要求 hostSectionIds 已经保存。

本轮验证了这项机制，尚未实现看板的初始化、缓存失效处理或已有会话对账。
没有恢复远程自动分区。原始 5.2 秒延迟的主因仍未确定，本轮不算其自然复现。

## 真实实验

实验通过 Codex 自带 app-server proxy 连接目标后台，没有猜测 daemon socket。
写入前核对 codexHome、五个既有远程副本的 ID 和名称。
随后实际收到来自侧栏移动的 11 次后台通知，与读回位置逐次对应，
因此证据不只是在另一个服务中看到同名分区或相同历史数据。

这是源码外的专用实验连接。后续业务接入仍须经过 App::connection，
不能把本次脚本作为业务旁路，也不把此结果算作完整客户端功能验收。

创建的空会话：

`01a1da49-cf3c-7f31-be66-787c59355728`

没有发送用户消息或启动模型轮次。独立收尾读取确认 turns 为空。

实验步骤与结果：

1. 核对五个既有远程映射，全部命中后台分区目录，名称一致。
2. 新建两个名称完全相同的空逻辑分区，分别移动本轮空会话。
   每次使用目标逻辑 ID、原生移动成功回执、实时逻辑成员关系、
   后台读回的 section.id 建立关系，不按名称或成员键的 local 前缀推断。
3. 两次读回时，文件里的对应映射均尚未出现；仍分别得到两个不同的后台 ID。
   后台通知也给出相应 ID。这覆盖了无已保存映射的情况。
4. 删除其中一个临时分区，确认旧后台 ID 从原生目录消失。
   再以相同名称重建，获得新的逻辑 ID 和后台 ID，旧缓存可以明确判为失效。
   这是失效检测与受控重建实验，不表示自动恢复逻辑已经实现。
5. 使用已经校准的两个映射再交替移动八次，每次读回均命中预期后台 ID。
   两次初始移动、一次重建后移动和八次复用移动，共对应 11 次后台变更通知。

没有注入延迟、并发重命名或其他压力。接口计时如下：

| 测量项 | 结果 |
| --- | --- |
| 两次初始侧栏移动的客户端处理 | 167.98 ms、104.31 ms |
| 两次随后读取实际位置 | 3.78 ms、2.35 ms |
| 八次复用映射的侧栏移动处理 | 49.55–199.46 ms，中位 127.77 ms |
| 八次随后读取实际位置 | 2.10–5.33 ms |
| 通知中的后台 ID 与实际读回对应 | 11/11 |
| 复用映射后命中预期后台 ID | 8/8 |

侧栏工具计时在 Linux 端，读回计时在 Mac 端。
以上不是鼠标拖动到页面完成的总耗时，也不包含整个校准流程的额外查询。
初始化整体耗时、本次未独立计量，不能把 2–5 ms 说成完整初始化时间。

## 建议的看板流程

1. 按已核验的来源、账号、主机 ID、逻辑分区 ID 管理映射。
   连接时读取并验证已有映射，检查对应后台 ID 存在、绑定无重复、名称符合配置。
   当前五个既有远程映射满足本轮目录检查。
2. 缺映射时，以专用空会话执行一次受控校准，读回后台 ID 并核对逻辑成员关系，
   然后保存到看板自己的映射记录。校准完成归档空会话，不增加业务状态分区。
3. 日常仍通过原生侧栏命令移动，成功后将实际后台位置与已验证映射比较。
   不在每次确认时重新等待全局映射文件保存，不仅凭成功回执显示完成。
   后台通知只触发复查或提供附加证据，写后读回仍是确认依据。
4. 后台 ID 消失、逻辑分区改变、来源或账号变化时，使对应缓存失效。
   仍存在的目标逻辑分区可以重新校准；逻辑 ID 本身已删除时，
   不能按同名分区偷偷重新绑定，需要明确的配置恢复规则。
5. 映射可靠后，再分页核对已有会话的实际分区和运行证据，制定历史补齐流程。
   保留已有人工选择，不从名字猜位置，也不借此次调查批量改变历史会话或标题。

src/native_sections/direct.rs 目前将 Catalog::load 和每次位置读取绑定，
确认循环因此会重读磁盘映射。后续应把映射的取得、校验和失效，与实际位置确认分开，
让位置确认复用已经验证的映射。这是看板侧的改动。
既有稳定映射场景原本也可能很快，不能把改动收益等同于解释了原始 5.2 秒。

## 仍待验证

- 真实新增主机的登记、认证与首次连接。本轮是在已连接主机上新建空分区。
- 切换账号、断线重连、后台重启和回执丢失后的恢复。
- 人工并发移动、分区重建与自动流转重叠时的保护。
- 看板映射记录的持久化与失效实现，以及已有会话的实际补齐。
- 真实客户端中的端到端性能与功能验收。

因此可以进入只改看板的方案实现，不能宣称远程自动分区已经恢复或完整可靠性已验收。
不需要向用户增加“待核对”业务分区；真正的失败应保留原状态并报告具体原因。
