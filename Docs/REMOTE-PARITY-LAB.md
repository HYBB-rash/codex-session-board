# 远程会话等价实验与维护成本

日期：2026-11-07，Asia/Shanghai。
基线：`b7acaa72fb62e2ffaf0d44292956a31d34bee036`，原日常版本 0.1.69。
独立工作树：`remote-parity-lab/notion-program`。本实验不合并、不部署。

## 判断

支持远程会话的增量维护成本为中等，有可复用的实现路径。
不需要再实现一套状态机，也没有证据表明必须维护第二套远端常驻服务。
当前 Mac 已有受管理的 app-server daemon，CLI 提供连接运行实例的 proxy；
隔离环境中，两个真实 proxy 已成功共享同一执行实例。

如果“完全一致”指同一组看板操作、同一套状态规则、相同的保存与失败语义，
现有证据支持继续实现。若要求跨客户端原子一致、任意版本永远兼容、
断线期间也知道真实状态或捕获所有短暂阶段，则超出了本地现有保证。
这些要求不能用增加重试或另一份远程状态机解决。

原型的按主机适配、时钟投影和发现逻辑，复用真实 Rust Store、
native_sections、titles 和 archive。另有独立故障模型与测试。
这能说明规则可共享，不是完整产品接入代码量或工期估算。
唯一业务库改动是公开已有的只读归档查询，供丢回执恢复复用；
日常看板的远程按钮、路由和数据库迁移尚未接入本原型。

## 已执行的验证

Rust 原型入口为 `examples/remote_parity_lab.rs`，32 项测试通过。
测试使用真实 Store、状态处理、标题队列和归档校验，通过受控 RPC 注入故障。
其中标题竞争、未校准时钟和分区 ABA 三项是限制反例。
它们通过仅表示反例可复现，不表示已获得强一致保证。

真实协议实验在 macOS 27.0.1 arm64、Codex CLI 0.167.0 上执行。
只在临时 CODEX_HOME 内创建一个专用会话及分区。
Responses SSE 使用本地确定性上游和回环 SSH 隧道，不使用真实模型或 API 凭据。
这是实际 Codex 进程和实际协议实验，不是只模拟 app-server 回包。

14 项基础实测通过：

| 项目 | 观察结果 |
| --- | --- |
| 共享执行状态 | 两个 proxy 读到同一 thread、turn 的 active / inProgress |
| 独立进程反例 | 相同 CODEX_HOME 的另一 stdio 实例读到 notLoaded / interrupted |
| 正常结束 | 放开 HTTP 屏障后 completed，完整答复和用户消息落盘 |
| 中断与恢复 | B 中断 A 的轮次；thread/resume 后新轮次正常结束 |
| 标题 | 1178 字符、2324 UTF-8 字节的标题完整读回 |
| 分区 | 创建后移动，thread/read 独立确认目标分区 |
| 归档生命周期 | 归档列表确认，再取消归档并从活动列表读回 |
| 非 authority 归档 | 独立 stdio 被 active writer 保护拒绝，没有中断原执行 |
| 隔离与清理 | 仅回环监听；实验进程、隧道和远端临时目录全部清理 |

proxy 是字节转发，不会把 JSON 行转换成 WebSocket。
首次按 JSON 行初始化超时；WebSocket 握手和帧封装后通过。
正式实现应复用现有 tungstenite，不能维护实验脚本中的手写帧编解码器。
中断后的恢复指启动新轮次，不代表继续同一次已中断的模型请求。
active writer 拒绝只在所测版本得到确认，不能代替客户端的资格检查。

## 风险逐项判定

| 风险 | 原型及证据 | 判定 |
| --- | --- | --- |
| 同 UUID 跨主机串写 | 分主机 Store、连接身份核对、混合主机页原子拒绝 | 可由适配器处理 |
| 主机重新登记 | 新 hostId 不继承旧人工确认 | 需显式迁移，不能凭名称猜测 |
| 标题正文截断 | 同步读取最新完整原生名称，不用列表缓存正文 | 共享原有标题规则 |
| 标题断线和旧回执 | 持久队列、读回后重试、旧版本不能清新任务 | 共享原有补偿规则 |
| 标题竞争 | 读后另一客户端改正文，随后无条件写覆盖 | 无 CAS 的既有限制 |
| 分区外部变化 | 旧位置拒绝；写后读回；Pinned 不自动移动 | 可复用原有权威模式 |
| 分区 ABA | 移走再移回后，旧位置看起来相同 | 无服务端修订号，客户端不可识别 |
| 原生写成功但本地失败 | 丢回执不假报备注成功，不后台重放旧状态 | 保留未确认，重新读取 |
| 自动状态与人工选择 | 阶段去重、审批及交互标记、恢复和完成 | 共享原有状态规则 |
| 历史与执行状态混淆 | 非 authority 禁止自动流转和归档 | 必须连接真实执行实例 |
| 跨机时钟 | 未校准反例；校准投影后复用现有规则 | 正式接入须建立真实校准或顺序证据 |
| 同轮新增用户输入 | 使用完整用户消息 ID，提示跨重启保留 | 不把 updatedAt 当输入版本 |
| 编辑和归档期间新输入 | 旧版本及原生未缓存新输入均阻止归档 | 共享原有完整输入校验 |
| 归档丢回执 | 重启先查目标主机归档列表，不重复写入 | 共享查询和确认逻辑 |
| 批量范围变化 | 按主机与项目冻结快照，保留版本 | 每项执行前仍须重新检查 |
| 一台慢主机阻塞其他主机 | 分主机 Store 与操作范围，屏障测试本机先完成 | 避免全局网络锁 |
| 移除最后一个项目 | 扫描来源独立于项目；已有主机继续扫描 | 需独立主机登记 |
| 项目目录失败 | 缓存主机继续可读，同时保留目录错误 | 明确降级，不假报全健康 |
| 多页慢扫描与重启 | 每轮推进一页，SQLite 保存 cursor，重启续扫 | 不必每次从首页重来 |
| 重复 cursor 和跨主机回包 | 明确失败，保留此前数据及进度 | 不删除缺项，不猜测归档 |
| 旧连接迟到结果 | 连接代次校验，拒绝旧位置及运行结果 | 可由共享连接管理处理 |
| 远程路径及项目重加 | 本机不解析远程文件系统 | 仍需目标主机项目归属适配与实测 |
| 新建输入页 | 已有后台 thread/start 不等于打开正确桌面输入页 | 目标客户端 UI 待验证 |
| 私有工具 pipe 更换 | 配置旧地址连接拒绝，当前注入地址成功 | 本地也受影响，不全算远程增量 |

时钟投影测试显式提供 offset，证明共享规则可继续使用。
它不证明真实校准已完成。生产需按连接采样、处理误差范围和重连后的变化；
无法确定终态与人工选择先后时，保留人工选择并报告观察不足。
分页原型保存历史进度，不声称动态列表的多页读取是原子快照。

## 维护与可靠性成本

| 部分 | 增量成本 | 原因 |
| --- | --- | --- |
| 状态规则、备注、输入确认 | 低 | 共享业务模型，避免两套修复 |
| 标题和归档补偿 | 低至中 | 既有持久队列及资格检查可复用，增加主机边界 |
| 连接和恢复 | 中 | SSH 子进程、WebSocket、代次、超时及重连 |
| 主机身份及已有数据接入 | 中 | 稳定身份、显式迁移、一次性旧数据接入 |
| 桌面分区、项目和新建输入页 | 中至较高 | 当前客户端映射与真实 UI 必须核对 |
| 多版本兼容 | 持续成本 | 升级时运行真实协议探针，格式未知时明确拒绝写入 |
| 跨客户端强一致 | 无法承诺 | 服务端没有所需 CAS / 分区修订保证，本地也没有 |

建议采用一个共享业务模型，加每主机的连接、身份和证据适配器。
远程 app-server 的进程管理继续复用现有客户端管理的 daemon。
不要为“远程”复制观察器状态机、标题队列、归档规则或另一套看板服务。
按主机显示能力与故障；离线状态不得冒充原生位置已修改成功。
自动状态只接受已确认执行来源，不能因为历史读取成功就清除观察异常。

日常升级的最小回归应包含握手、双 proxy 同实例、审批标记、完整输入、
标题幂等、归档拒绝、丢回执、重连和持久数据恢复。
本次仅测试一个实际版本，不承诺任意客户端和 CLI 版本均兼容。
桌面 UI、新建远程输入页、远程项目多根目录和工作树仍需专项验收。
这些是正式接入前的明确工作项，不能拿本实验通过代替。

## 复现与门禁

在本工作树执行：

```bash
cargo test --locked --offline --example remote_parity_lab
cargo clippy --all-targets --locked --offline -- -D warnings
python3 outputs/remote-parity-lab/live-proxy/remote_parity.py --host HOST --codex CODEX_PATH
python3 scripts/verify_acceptance.py --report outputs/remote-parity-lab/acceptance.json
sh scripts/verify_context.sh
./scripts/check
```

真实探针会在给定 SSH 主机创建并清理专用临时环境，不操作原有工作会话。
输出目录保留原始证据与脚本，属于运行数据，不进入源码分发包。
31 条冻结需求、参考模型和锁未改变；新增测试已绑定并纳入源码指纹。
原型测试不能替代既有 14 项外部验收缺证，发布判定以当前构建完整门禁为准。
