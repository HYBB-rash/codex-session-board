# 远程自动分区与已有会话补齐

实施日期：2026-11-14 至 2026-11-15。
来源基线：91a4fe847140ad54daa744519b0112e271527ab4。
本任务在独立工作树实现，不修改 Codex 桌面端、版本清单或日用配置。

## 已实现的行为

远程扫描、状态观察和人工修改统一使用原生分区位置。写入后复用已经校验的后台
分区目录确认实际位置，不再等待客户端全局状态文件防抖写回。

映射按客户端 owner、账号、状态逻辑 UUID、主机和已核验的远程来源保存。
重连会重新核对来源、实时逻辑目录及后台分区。已有的完整映射经过校验后复用；
不存在的后台 ID、名称不匹配、重复或相互冲突的映射不能用于业务移动。

缺少映射时，新建一个专用的原生空会话，逐一移动到五个已配置的逻辑状态分区，
分别读取客户端实时成员和远程后台实际分区，再次读回确认位置未变后保存对应关系。
全部映射确认后，归档专用空会话并独立确认归档结果。
整个过程不发送用户消息、不执行模型轮次，也不修改 Codex 安装资源。

专用空会话使用原生分页历史模式 `paginated`。校准记录在创建前写入请求 UUID，
创建后保存原生线程 UUID、初始标题和历史模式。标题包含本次请求 UUID；
每次操作均检查来源、目录、名称、实际状态和空历史证明。
持久模式通过 `thread/turns/list` 的摘要空页与空游标确认没有轮次，并比较前后两次
线程元信息，不能仅凭 `includeTurns:false` 的空 `turns` 数组认定会话没有历史。
该模式不依赖当前真实后台尚未支持的完整历史 `list_turns` 读取。
未 materialized 时，官方实现会用每次读取的当前时间合成 `createdAt`、`updatedAt`
和 `recencyAt`。一致性检查忽略这三个合成时钟，仍比较身份、名称、模式、状态、
分区及其他实际线程元信息，避免将正常读取时间变化当作用户操作。
用户改名或开始使用该会话时，停止管理并保留该会话。

普通错误不能当作空历史。首次输入前，原生后台可能尚未 materialized。
分页模式的 `thread/turns/list` 和旧模式的 `thread/read` 只在针对同一个 UUID 返回
各自指定的 `-32600`、明确说明首条用户消息前不可用的错误时，才采用这条原生证明，
继续执行同一套身份与状态检查。其他方法、错误码、UUID 或普通读取失败均拒绝回退。
已知旧探针如果已经不存在，必须遍历完整活动和归档列表，并再次读取确认缺失，
才释放旧记录；这与创建回执不明的情况不同。

创建回执不明时保留请求记录，禁止自动重复创建。
显式恢复入口 `/api/native-calibration/reset` 要求确认标志、匹配的请求 UUID 和来源，
且只能清除尚未拿到线程 UUID 的记录，不操作可能存在的真实会话。
专用会话在待清理期间不会进入业务发现、标题同步、状态观察和看板列表。

## 已有远程会话

首次切换原生分区时，逐条处理旧兼容数据，进度及待确认移动持久保存。
默认区域中的旧会话会依据原有人工状态、可信实时状态及已有观察结果补齐位置。
备注、输入版本、人工选择时间和阶段锚点保留；不会批量重写标题。

已经处于原生状态分区、用户自定义分区或置顶区域的会话，以实际原生位置为准，
不会因为旧兼容状态而搬走。迁移期间有人输入或移动会话时，重新核对版本和输入，
旧请求不能覆盖新的用户选择。

迁移首次启动时间持久保存，移动确认后只建立一次旧阶段基线。
即使在移动完成、建立基线前退出，也使用同一个时间边界处理重启后的新终态，
防止重放旧事件或吞掉真正的新完成事件。缓存中的未确认新输入继续阻止归档。

## 重连与分区重建

断线、移动丢回执或归档丢回执后，先读实际结果，不盲目重复写入。
客户端分区连接按操作重新建立；后台连接只在传输失败时失效，
结构化业务错误不会无谓断开连接。所有后台连接继续经过 `App::connection`。

同一个逻辑 UUID 的后台分区被重建时，丢弃失效后台映射并重新校准。
逻辑 UUID 被删除后，即使创建了同名分区，也不会按名称自动接管；
应显式更新状态分区配置。账号或来源改变时，不在新来源清理旧来源的会话。

## 验证记录

状态机测试覆盖冷主机五项映射、无磁盘写回、重启复用、创建回执不明、
标题接手、丢回执、跨时刻读回冲突、后台重建和逻辑 UUID 删除。
旧会话测试覆盖人工状态、备注、输入、阶段基线、迁移中退出和重启后的新终态。

服务集成测试连接真实编译服务、独立 SSH fixture、客户端分区协议 fixture 和远程
原生后台 fixture，验证缺失全部映射、旧会话补齐、移动与归档丢回执、离线缓存、
重连后的新完成事件以及专用会话隔离。fixture 不替代真实客户端验收。

实机诊断入口：

```text
cargo run --example remote_sections_probe -- 配置文件 主机ID 私有实验目录 已核验分区端点
```

入口使用隔离配置副本与数据库，去掉目标主机的磁盘映射以验证冷校准；
数据库存在业务会话时拒绝运行。重复运行复用本实验的恢复日志。
可附加 `--cleanup 已记录的专用空会话ID`，只清理该来源已有的实验记录，
并通过原生空历史或完整缺失检查确认结果。

最终验证结果及实机限制在任务完成记录中登记。
本任务没有安装、重载日用插件或批量移动真实业务会话。
完整 31 条需求的目标环境验收仍按项目现有证据分别判定。
