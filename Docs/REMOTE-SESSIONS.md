# 远程会话第一阶段

2026-11-07，源码版本 0.1.59。在原仓库实现，尚未部署到日常看板。
远程连接来自当前 Codex 客户端，复用已有的本地只读工具桥接。
不需要给远端安装另一套看板，不公开本地 HTTP 端口。

## 行为

- 展示本机和远程会话，远程卡片显示主机名称。
- 项目按主机区分，同名项目和各主机的默认工作区互不混淆。
- 远程备注和五种人工状态保存在本地，支持刷新、重启及断线时编辑。
- 点击卡片使用已保存的原始会话 ID 和主机 ID 打开原会话。
- 远程状态初始为待判断，不从历史完成状态推断当前执行情况。
- 远程不自动流转，不修改标题或原生分区，不支持新建和归档。
  界面隐藏或禁用相应操作，后端也在连接任何写入接口之前拒绝。
  本机继续沿用原有的原生权威状态及操作流程。

## 数据与读取边界

远程数据单独保存在同一 SQLite 库的 remote_sessions、remote_projects 表，
不改写原有本机会话、状态、备注、标题队列和设置。
卡片使用包含 codex 来源、hostId 和 threadId 的稳定身份，
同一 UUID 在本机或不同远程主机上可以分别保存，不相互覆盖。
保存检查状态版本和会话元数据版本；更新时间变化会拒绝旧编辑，
这不是对新用户输入的语义识别。

配置中 sidebar_socket 与 sidebar_caller 都存在时启动远程发现，
沿用 poll_seconds、page_size 和 max_pages。只读连接仅增加 list_projects，
按主机分页调用 list_threads 的 history/codex 来源。
每台主机使用独立连接；重复分页、达到上限、连接失败均明确报告，
保留已读卡片与人工内容，后续扫描继续尝试。

list_projects 的项目资料可能暂时缺失，因此缓存项目与主机继续保留。
只有配置的 sidebar_state_file 中完整有效的 remote-projects 登记表
确认移除后，才移除对应缓存分类。该内部格式读取失败时保留分类并提示。
真正移除项目后，会话归该远程主机的默认工作区，筛选不会跳到本机。
远程路径不在本机做目录解析或 Git 检查。
首次发现依赖客户端登记的远程项目，没有项目且从未缓存的主机尚不自动枚举。

## 验证

新增回归覆盖跨主机身份、旧本机数据保留、版本冲突、持久保存、
原子失败、分页去重、重复游标、部分项目资料、单主机失败隔离、
本机权威模式下的远程路由、禁用写操作及实际二进制 HTTP/MCP 链路。
测试绑定增加到原编号下，冻结的 31 条需求、参考模型和锁保持不变。

使用生产库的只读备份启动隔离实例，关闭运行观察和标题写入。
真实浏览器展示 120 条本机和 41 条 MacBook 远程会话，
项目筛选结果为 9 条，远程默认工作区为 32 条。
实际验证备注、人工状态、项目移除后的主机范围、禁用新建、
服务重启、断线编辑及恢复后的保留。
跳转 URL 的原始会话和主机参数已核对，原生命令返回成功；
实际客户端显示对应的远程会话标题、项目与原有内容，没有发送消息。
浏览器和客户端截图已经审阅。
