# 默认工作区无项目新建方案

## 范围与成败标准

2026-11-11 用户要求先制定方案，允许通过实验消除影响方案的不确定性。
本轮不实现业务功能、不部署、不发送模型输入。
当前安装包为 26.1103.60933，ASAR SHA256 为
23529d915340b1e821e98e6380ea9c9cfd8bde9327f236a5d1453cd24646fa03。

本机看板明确选中默认工作区后，新建输入页应明确处于无项目状态。
用户随后发送输入时，也不能沿用上一个项目的目录或项目指令。
项目内新建继续使用所选项目；全部项目、搜索、远程默认工作区不隐式扩展范围。
账号级配置、全局技能、模型与权限配置不属于此次清除项目关联的范围。

## 已核实事实

当前前端在默认工作区、全部项目和搜索模式都发送空对象。
后端统一打开 codex://threads/new。省略 projectId 不是新的修复措施。
当前接口还不能区分默认工作区的明确无项目意图和未指定创建目标。
projectId 为 null、空字符串或无效项目会报错，不能将它们当作清除标记。

默认工作区是本机未匹配到登记项目且没有归属异常的会话集合，没有固定根目录。
项目归属根据实际 cwd、已登记根目录和关联 Git 工作树计算。
因此验收必须同时检查原生项目关联和真实工作目录，不能只检查 URL 或显示名称。

官方命令文档区分 New chat 与 New standalone chat。
Linux 独立会话快捷键为 Ctrl+Alt+O；公开深链列表没有说明明确清除项目的参数。
文档来源：https://learn.chatgpt.com/docs/reference/commands

## 本轮实验

在正在运行的客户端新建页，起始项目栏显示具体项目，输入框未显示正文。
通过 Computer Use 按 Ctrl+Alt+O，随后截图显示项目栏变为“选择项目”。
主代理没有输入文字或按发送键。这证明本机存在可用的原生无项目入口。
页面之后出现本轮操作之外的会话变化，故停止真实窗口实验。
没有据此认定草稿保留、多窗口影响和首轮工作目录均已验收。

随后只读观察到一条会话使用客户端生成的 Documents/Codex 日期子目录，
该目录未匹配任何已登记项目。这不是主代理发送的专用测试会话，仅作旁证。

### 隔离探针

outputs/standalone-new-session-plan-20261111/probe.cjs 从上述安装包提取
startNewConversation 原函数，用替身依赖执行六个分支，全部通过。
确认省略 activeProject 不提供路由 project 字段，而 null 明确表示无项目。
首页无绑定草稿时可以保留原草稿身份和 focusComposerNonce。
freshDraft 或绑定草稿会触发新草稿身份；本次需求不额外强制 freshDraft。
从特定项目路由进入时会通过原生 setter 清除全局项目选择。
因此保留原生命令语义，不承诺其他窗口完全不受项目选择变化影响。

route-probe.cjs 在内存中给原解析器和原导航处理器增加独立入口，
九个路径与命令分发断言通过，两个修改后的完整 JS bundle 语法检查通过。
原安装包返回 null；修改后的解析器得到 newProjectlessTask，
真实导航处理函数转发 run-command/newProjectlessTask 到替身窗口。
普通新建保持原结果；新入口拒绝附带 prompt、projectId、多余路径及片段。
这些实验没有安装补丁、触发真实深链或验证 renderer 收到命令后的最终状态。

可重跑：

```bash

node outputs/standalone-new-session-plan-20261111/route-probe.cjs
```

## 推荐落地方案

先在社区客户端构建中增加受管的无项目新建功能，再接入看板。
使用独立深链 codex://threads/new-projectless，不能在旧 new 路径上追加一个
旧客户端会忽略的参数。该路径是本次拟增加的社区扩展，不是官方已有契约。
当前旧客户端对它返回 null，避免误执行普通新建。

客户端解析器将路径转换成独立动作，主进程转发已有
run-command/newProjectlessTask。renderer 原有处理器继续执行
startNewConversation(scope, {activeProject:null})，复用权限、草稿和目录语义。
不重写 renderer 新建流程，不直接改偏好文件，不模拟键盘。

补丁纳入社区构建功能及其安装能力报告，不直接修改正在使用的 ASAR。
看板通过配置的受管启动器读取能力后再发送入口；能力报告应关联当前安装包，
缺失或安装包不匹配时拒绝请求并提示更新，不能仅依赖一个永久布尔开关。
启动命令只能证明已发送打开请求，界面提示不将它说成最终项目已验收。
不将该功能依赖绑定到当前仍有生命周期问题的分区 socket。

当前 create_thread 工具已有 target.type=projectless 能力，但 prompt 必填，
会创建任务并启动执行，不适用于只打开新建页，也不以空字符串尝试绕过。
已核对的现有工具目录没有找到可直接调用的无项目草稿导航接口。

## 接口设计约束

明确区分指定项目、明确无项目、沿用既有未指定目标行为。
建议使用单一可选 target 字段表示 standalone，保留现有 projectId 路径。
禁止同时指定 standalone 目标和 projectId、hostId 或远程草稿 requestId。
仅点击时明确选中本机默认工作区发送 standalone，后端不保存当前项目状态。
HTTP 与 board_new 的 MCP schema、参数验证和错误语义同步扩展。
客户端不支持该能力时明确提示，不能静默回退到会继承旧项目的普通新建。

## 实施顺序与验证

1. 在社区客户端功能目录实现受管的解析与命令转发补丁、能力报告。
   用当前包及目标升级包验证唯一匹配、完整语法检查和不支持时拒绝。
2. 安装实验构建后，在专用窗口验证新入口及草稿、全局选择和目录行为。
   客户端改包需要重启才能验证，协调窗口使用并保留原包回滚。
3. 看板增加 target=standalone 的 HTTP/MCP 互斥验证和能力检查，
   前端仅本机默认工作区发送；普通、明确项目及远程请求保持原语义。
4. 完成自动回归、专用真实会话首轮验证和发布门槛，再单独部署。

不通过先改全局偏好再打开页面的两步操作模拟无项目新建。
不使用任意临时目录、用户目录或上一条会话 cwd 冒充明确无项目语义。

验证至少覆盖：

- 先使用项目 A，再从默认工作区新建；项目栏和后续实际 cwd 不沿用 A。
- 先使用项目 B，重复上述过程；核对不是仅清除了某一个固定项目。
- 项目移除后的默认回退，以及项目列表加载失败时的新建行为。
- 具体项目 A/B、全部项目、搜索和远程入口的既有语义。
- 未发送草稿、多窗口、连续点击和请求期间切换筛选。
- 客户端能力缺失、连接失败及升级后的协议不匹配。

自动回归覆盖请求构造、互斥字段、HTTP/MCP 一致性和错误时不执行普通新建。
真实客户端独立验证输入页，首轮运行需要专用会话，不能用模拟启动成功代替。
原 31 条验收需求、参考模型和锁保持不变，完整发布仍遵守既有 release_ready 门槛。
