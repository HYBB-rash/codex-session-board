# 2026-11-12 面板状态错乱

本次故障有两个独立原因，原始现场及完整时间线保存在 outputs/state-incident-20261112/REPORT.md。

18:24 的升级命令显式选择 config-0.2.92.json，在18767启动正确生产库。
18:33 的插件MCP未绑定该配置，回落到11月6日的config.json，在8767内嵌启动另一实例。
两者都是0.3.25，因此只核对版本与工具的发布验证未发现配置与数据分叉。
旧库仍缓存155条未归档记录；截图中的两条会话实际都在原生归档列表。
旧库的review与in_progress是历史缓存，不是对当前原生状态的有效读回。
正式库中归档标记和备注仍在，恢复不合并旧库、不按标题前缀批量改列。

正式实例还有当前客户端存储兼容问题。原生分区及会话别名已位于
electron-owner-atoms:<当前账号>，由electron-renderer-content-owner指明当前账号。
原代码仍只读取electron-persisted-atom-state，导致“客户端分区映射无效”。
修复共用账号读取函数，分区映射与别名均使用当前账号。
存在当前账号但其数据缺失或类型错误时必须拒绝，不回退全局或其他账号。
只有无当前账号标识的旧客户端保留旧格式读取。各分区继续按既有ID和后端目录严格匹配，不按名称重认领。

新增三项回归覆盖当前账号优先、缺失或无效账号拒绝、别名不回退。
原实现的回归失败准确复现现场分区错误；冻结31项、独立模型与锁不变。
本机默认配置入口已原子指向正式配置，旧默认配置及两套库均保全。
必须重建缓存了8767地址的MCP连接，并在同一后端身份上验证恢复。
新二进制与实际面板结果以outputs/state-incident-20261112/recovery.json为准。
恢复期间暂缓定时归档，避免积压任务因重新读回立即执行。原设置保留待审阅。

这次迁移的验证遗漏是服务版本与MCP版本相同却未核对其配置和数据库身份。
完整业务验收缺证仍保持pending，不发布stable。长期防复发方案在恢复后另行讨论。
