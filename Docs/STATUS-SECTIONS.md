# 状态分区扩展

2026-11-06，用户明确要求撤掉原自定义分区，以看板六状态组织会话，
并在以后状态变化时移动原生会话。此授权替代原契约对移动侧边栏分组的禁止。
状态名称、顺序、人工确认规则及不发消息、不启动执行、不真实归档的边界保留。

冻结的 31 条需求、独立参考模型及锁不修改。原 BOUNDARY-001 和 excluded
关于不移动分组的断言继续用于默认的 `sync_sections=false` 兼容模式。
该基线的自动通过不能证明开启分区同步后的扩展验收完成。
新增测试纳入同一测试清单，验证状态持久化、失败补偿、按 ID 移动及连接边界。

## 原生接口

已检索官方文档，并读取 Codex 应用功能页；未找到分区写入协议的公开说明。
实际协议依据本机客户端随附的 codex-app-tools/server.mjs 和真实只读调用核实。
原生布局对已加载会话使用 client-new-thread 别名。通过外部配置
sidebar_state_file 只读客户端的 thread-client-id-v1 路由映射，规范化后再比较，
不把别名与原会话 ID 不同误判为未移动。别名尚未落盘时暂停该轮对账。
映射键中的 local 是客户端路由命名空间，实际主机沿用配置及发现范围。
该字段来自当前客户端内部格式，格式更改、映射冲突或读取失败时报告异常。
使用 CODEX_APP_TOOLS_PIPE_PATH 对应的原生 Unix socket，
每帧为四字节小端 JSON 长度和 UTF-8 JSON。响应上限为 8 MiB。
这条连接与 app-server 的 WebSocket 连接分开，路径由部署配置提供。

长期运行的连接只允许 list_threads 与 move_thread_to_sidebar_section。
调用方上下文和目标会话 ID 分开。迁移中的创建与删除由本次任务单独执行，
守护进程没有创建、删除、发送消息、执行任务或归档工具权限。
连接核对当前用户所有权、socket 的 0600 权限及父目录不可被其他用户写入。
客户端重启后原路径消失时，只在同一配置目录内查找唯一的 .sock 后继，
并重新核对所有权与权限；存在多个候选时报告异常，要求更新配置。
连接和读写使用整轮预算。保存后的单会话移动最多三秒；
后台读取全部分区及读回使用 rpc_timeout_seconds，最多二十秒，失败后重新连接。

## 同步与验证

Store 是状态来源，原生布局是实际位置来源。全量对账无需另存易失队列：
重启后重新比较已持久化状态与原生布局即可重试。
保存后立即尝试单会话移动，不因读取全部主机摘要延迟保存；
返回分区待同步，后台独立读回位置后确认。同一进程的立即同步与后台同步共用锁。
锁忙时返回状态已保存、分区待同步。写前重读状态和版本，写后再读取布局并
与最新状态比较，防止旧回执宣称新状态已同步。回执丢失通过实际位置消歧。
历史建议即使不改变状态版本，也参与对账。

桌面运行观察的一次完整发现确定可同步集合，历史扫描不覆盖该集合。
扫描暂时缺失的缓存会话不参与移动，写前再次核对资格。
超时连接下一轮重建，并轮换起始会话，防止持续失败的首项饿死后项。
工具只移动单个会话，保留其他会话、ChatGPT 成员和项目。
后台对账要求分区 ID 及名称与配置和六状态同时一致，缺失或改名时报告异常。

扩展实测需记录迁移前布局和数据库备份，独立读回六分区顺序及会话位置；
随后在已有会话状态变化后再次读回。受控测试验证关闭标题仍移动、
重启补偿、失败隔离、回执丢失、并发更新及历史建议变化。
其他原生 UI 与全量发布证据不足时仍保持 release_ready=false。
