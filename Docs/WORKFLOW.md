# 业务流程与操作边界

配置、命令与副作用见[配置与命令](CONFIGURATION.md)；
Agent 开发约定见 [AGENTS.md](../AGENTS.md)。
本页保留业务约定，不作为启动真实任务或修改服务的授权。

## 调度与续试

只有 `待办事项` 能开始新轮次；`未开始`、`计划中` 不派单。
调度器只读取任务元数据，管理状态、聊天路由、有限的调度诊断及执行收据；
报告正文、轮次文章和审阅原文由执行聊天负责。

创建聊天、发送意图、执行回合和状态写入分别保存检查点。
观察到匹配回合真正运行后才发布 `进行中`，已完成的回合可直接提交审核。
发送或写入结果不明时先核对，进程重启或重复定时检查不直接重发。

人工续试与有限自动续试保留聊天、轮次、权限、快照和文章。
等待审批或输入时不自动绕过；续试不代表新增权限，也不自动消除阻塞。
项目上下文契约和 helper 命令保存在轮次记录中，续试沿用原记录及执行收据中的模型和权限参数，
不通过改配置跳过已有约束。

## 历史、文章与交付

已绑定的历史索引和轮次文章保持独占，执行聊天维护正文、报告、审阅归档及读回。
完成收据检查任务、轮次、执行 token、哈希及归属声明，并核对已知路由。
调度器验证收据，正文是否完整读回由执行者声明，这不能代替 Herman 的人工审核。
任务主页、历史索引和轮次文章的结构见 [execution-templates/](../execution-templates/)。

正文比较测试读取 [content-comparison.json](../tests/fixtures/content-comparison.json)，
其中保留原 Python 比较器提取的输入及预期结果，不需要 Python 源项目。
调度器现行入口不采用旧的“由调度器读取并追加任务正文”工作流，详见[迁移说明](MIGRATION.md)。

## 知识归档与上下文

归档准备阶段就可能创建基础上下文页并向项目页补充入口链接。
知识更新会保存来源、生成并校验方案，再更新专题、上下文和收据，最后更新任务状态；
不能把方案校验理解为此前完全不会写入 Notion。
不完整读取、来源变化或不确定写入保留检查点以便核对。
项目上下文 helper 向执行聊天提供上下文，命令和配置示例见[配置与命令](CONFIGURATION.md#项目上下文-helper)。
它会按需建立项目上下文页并补充项目页入口，因此获取上下文也可能写入 Notion；
不能仅凭命令名中的 `context` 或归档配置的停用状态将其视作只读操作。
返回的摘要和专题目录不等于已阅读专题正文，执行聊天仍须自行读取相关专题并记录实际使用情况。

文件锁只保护使用同一数据目录的程序，Notion 的读取和属性写入仍是分开的操作，
不能把本地锁当作远端原子操作的保证。

## 测试与真实服务

普通 `cargo test` 使用临时目录、模拟客户端、本机测试套接字和本机 HTTP 服务，
不连接真实 Notion，不发送真实聊天消息。
离线测试与线上验证分开记录，自动化通过不能代替人工审核。

[examples/live_validation.rs](../examples/live_validation.rs) 是显式运行的线上验证工具，
可以创建带标记的测试项目、计划中任务和归档样本。
创建前保存意图，结果不明时保留记录核对，不自动重复创建。
它独立于 `cargo test`，实际运行会写入 Notion，激活测试任务后会触发真实执行；
运行前必须获得明确授权。
既往真实验证、证据和验证范围见[部署记录](DEPLOYMENT.md)，不代表当前实时服务状态。

## 与旧部署交接

Rust 使用独立配置；本机已记录的切换沿用原数据和任务目录，
保持已有任务检查点、聊天和文章归属连续。
`import-config` 不自动接管旧 `data/`、`tasks/` 或 systemd 服务。

需要切换正在运行的部署时，先停止旧入口，在锁保护下备份检查点和任务文件，
核对其中的绝对路径，再让新服务使用同一份连续状态。
不要让两份独立状态库同时调度同一个追踪表，也不要用旧备份直接覆盖已产生新结果的状态。

[deploy/](../deploy/) 提供本机 systemd 单元，其他主机须先调整路径。
普通开发不启用、替换或调整运行中的服务和定时器；
真实切换与回退须明确授权，按[部署与回退](DEPLOYMENT.md#回退)核对。
