## 首轮业务交付

`codex/b2-card-actions` 在 B1 的最终快照上判断卡片操作。调整、拖动、单卡按钮和批量名单现在读取 `index.html` 的 `cardActions`。归档与新输入确认进行期间，界面即时禁用相应控件。卡片展示仍使用 B1 的最终列，旧 `completed` 在日常模式进入待归档。

根 `/api/sessions` 用一次索引查询标出已认领的归档；即使另一页面尚未收到批次列表，也能显示待核对。原有待核对卡仍可手动调整，重复归档由后端拒绝。在线远程目录只有元数据时，页面提供只读卡。主机库发现会话后恢复编辑。

## 离线面板与 D 的分派

在协调者指定的 `f2a09ef` 基线上，独立 Chrome 从真实 `resources/read` 回执载入面板。iframe 禁止网络连接，宿主转交 `tools/call` 给同一 fixture 启动的 MCP 程序。在线远端显示“归档”，有新输入的本机卡显示“确认待归档”，离线缓存卡禁用调整和拖动。点击列按钮后，`board_archive_batch_start` 名单和 `board_archive` 版本都只属于目标远端。挂起桥接回执时，卡片和列按钮禁用。随后单卡确认仅发送对应版本的 `board_update`。目标远端的原生归档写入一次，本机与另一台同 UUID 主机均为零。

初次用 Node 启动 MCP 子进程，服务正确拒绝属于不同客户端后台的请求。测试改由 Rust fixture 同时启动看板和 MCP，让它们拥有相同父进程，并通过 stdio 将浏览器请求交给 MCP。真实后台身份校验始终开启。

该阶段独审在 `9ee47c2` 的独立副本复跑 4 项 HTTP 与连接测试、5 项离线面板与远程归档测试，全部通过。最终重基到协调者提供的 A、E1 组合头 `fd6aeff666efa9f7e5164d7d008004ad19a4591f`。离线面板先打开并收起 Vue 回复预览，再执行相同的归档与确认。挂起确认后的快照响应时，页面已经采用 A 返回的完整确认卡片；核对会话身份、输入标记及整条回执后才放行刷新。
