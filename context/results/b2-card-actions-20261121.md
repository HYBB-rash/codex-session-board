# B2 · 卡片操作资格交付

`codex/b2-card-actions` 在 B1 的最终快照上判断卡片操作。调整、拖动、单卡按钮和批量名单现在读取 `index.html` 的 `cardActions`。归档与新输入确认进行期间，界面即时禁用相应控件。卡片展示仍使用 B1 的最终列，旧 `completed` 在日常模式进入待归档。

根 `/api/sessions` 用一次索引查询标出已认领的归档；即使另一页面尚未收到批次列表，也能显示待核对。原有待核对卡仍可手动调整，重复归档由后端拒绝。在线远程目录只有元数据时，页面提供只读卡。主机库发现会话后恢复编辑。

## 实际请求与读回

复验使用 Linux 临时库、回环 HTTP 服务、隔离 Chrome profile、受控远程连接和原生 RPC fixture。按钮矩阵、旧出处与各作者的测试 ID 见[任务卡](../tasks/active/b2-card-actions-20261121.md)。

| 操作 | 读回 |
| --- | --- |
| 在待归档列点击归档 | 清单仅含 `Local` 和 `Online`。两者均为状态版本 1、输入版本 0。同列的已归档、待核对、有新输入的卡均跳过。仅有目录记录的卡显示在未归列区。 |
| 单卡确认新输入 | `/api/state` 成功后按钮改为“归档”。再次点击才登记该卡，状态版本 2、输入版本 1。 |
| 挂起真实归档 POST 或确认输入 POST | 卡片禁用调整、拖动和归档，列按钮也禁用。再次点击没有增加批次。 |
| 在线主机来源改变或断线 | 用原按钮的版本提交状态与归档均被拒绝。隔离本机归档成功案例另由 `archive_flow` 的桌面写入器测试验证。 |
| 在线归档丢回执 | 界面显示待核对。直接重试旧归档请求被拒绝，RPC 日志只有一次 `thread/archive`。 |

## 审阅与回修

独立审阅在 `bf4bdd1` 发现两处 P2。挂起 `/api/state` 时页面仍显示可操作；非原生分区模式的远程目录占位卡也显示可编辑。回修后，浏览器实际挂起两种 POST 并核对控件，目录占位卡的直接 POST 被拒，主机库补齐记录后恢复可写。

独立复审通过的业务提交是 `ae9719f6223ed97717ed77b4b17936413a134e77`，基线 `3de9e0f00f5458eda255b59e81cc54e63818f071`，包含远端 B1 `dce3536b70459c2962fa225320ecb88a8cde7522`。作者在此提交通过 134 项相关 Rust 测试、全目标 Clippy、`./scripts/check` 和上下文检查。独立审阅另跑 28 项 Rust 测试、64 个反馈场景和 60 个筛选场景。

T3 对照在同一提交的独立副本执行。列按钮改用等价的 `.bind()` 后仍通过。注入“已归档只读卡进入名单”时，真实 POST 多出 `Archived`，后端拒绝该项，测试在读取批次后退出 101。恢复源码后浏览器测试再次通过。原始日志在 `/tmp/b2-t3-independent-ae9719f/`，独审日志在 `/tmp/b2-independent-ae9719f-*.log`。

本项交付本地分支，主线由合入协调者串行写入。E3 的十卡中断恢复和筛选作者的端到端验收另行交付。真实客户端与完整 31 条验收仍待相应环境取证。

## 离线面板与 D 的分派

在协调者指定的 `f2a09ef` 基线上，独立 Chrome 从真实 `resources/read` 回执载入面板。iframe 禁止网络连接，宿主转交 `tools/call` 给同一 fixture 启动的 MCP 程序。在线远端显示“归档”，有新输入的本机卡显示“确认待归档”，离线缓存卡禁用调整和拖动。点击列按钮后，`board_archive_batch_start` 名单和 `board_archive` 版本都只属于目标远端。挂起桥接回执时，卡片和列按钮禁用。随后单卡确认仅发送对应版本的 `board_update`。目标远端的原生归档写入一次，本机与另一台同 UUID 主机均为零。

初次用 Node 启动 MCP 子进程，服务正确拒绝属于不同客户端后台的请求。测试改由 Rust fixture 同时启动看板和 MCP，让它们拥有相同父进程，并通过 stdio 将浏览器请求交给 MCP。真实后台身份校验始终开启。
