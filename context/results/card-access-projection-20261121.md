# 卡片写入资格由根快照给出

`codex/card-access-projection` 承接已合入的 B2 `bc89a5f3af94e0b2d1c7be24abb65c946cf35aec`。首轮独审与四联回执绑定实现 `ecb01fc096c6767c9535e58b8fd9d64a91867596`。接入远程归档门禁 `2766f8d` 后，独审在 `e02825b` 重跑连接资格及离线面板。接入远程保存门禁 `73da0c3031f3f78846b89ad4263303e7f8bb6e11` 后，`git range-diff` 核实三个补丁逐笔相同；各轮项目检查和定向结果分别保留在证据目录。

网页 `/api/sessions`、MCP `board_snapshot` 和 A 的保存回执经过同一份根快照投影。原实现对普通可写本机卡省略 `readOnly` 和 `canArchive`，冻结六列的远程兼容记录也省略 `readOnly`。现在 `App::annotate_connections` 将这些旧数据的既有含义转换为两个明确的布尔字段。`canOpen` 继续只负责导航。

| 来源及操作 | 读回 |
| --- | --- |
| 四列、五列根库旧远程记录 | `readOnly=true`、`canArchive=false`。保留原备注、状态版本和库内 `completed`。 |
| 冻结六列的同一份旧数据 | `readOnly=false`、`canArchive=false`。真实兼容保存仍按复合 ID 返回本卡；打开时保留主机身份。 |
| 外部 `list_threads` 分页，一台失败、一台成功 | 两台会话均保留在根快照。单凭外部清单不会获得受管写入权，两个标志分别为 `true`、`false`。 |
| 托管在线目录卡 | 只读可打开；主机库发现后才可修改；断线恢复只读。 |
| 普通本机可写卡 | 两个标志分别为 `false`、`true`。两空格保存后回执、刷新前页面和读回完整 24 字段相等。 |

`cardActions` 直接读取这两个字段，继续处理当前列、新输入、已认领批次及页面提交状态。浏览器对照在真实可写远端卡上仅切换导航能力，编辑、拖动和待归档按钮应保持原资格。旧页面误禁用了它们；新页面通过。缺少明确允许的权限时，当前页面禁用相应操作。后端提交时仍按真实连接、来源和版本核对。

Fedora 实现头已通过官方 UI 全组 8 项、HTTP 资格 4 项、旧缓存归列 3 项、目录 7 项、外部清单与兼容路由 8 项、离线面板及远程隔离 7 项。隔离数据库的 11 个编辑场景全部通过，开发服务已停止。全目标 Clippy、项目检查、上下文检查、源码包预检通过，需求、独立参考模型、锁和绑定均未改动。

独立复审在同一实现头通过 24 项定向。HTTP 与 stdio MCP 分别读回权限，逐项改变一张卡权限时只更新本卡按钮，另一张远端卡维持原状。临时恢复“禁止导航即只读”会使浏览器回归失败；恢复代码后通过。原始材料在 `independent/`。

E2a 可直接消费 `cardActions`；保持被点击卡片的复合 ID，跨卡导航仍读目标卡的 `canOpen`。T0 已按 B2 实际合入头登记保留的观察测试。E2a Fedora 作者也已在其交接文件中确认采用同一 B2 主线。

两次原失败、真实 HTTP/MCP 测试、外部扫描、兼容旧记录及四联回执见 [Fedora 只读资格证据目录](/home/herman/.codex/visualizations/2026/11/21/01a1fc80-61f5-76e1-80a3-ec068a3fab21/card-access)。
