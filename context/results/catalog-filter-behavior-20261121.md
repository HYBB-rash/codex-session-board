# 远程目录筛选测试裁决

T0 原 126 项中的 `test::ui_layout::host_catalog_filters_preserve_cached_rows_and_isolated_native_drafts` 保留测试 ID 和验收绑定，替换 `report["cases"] == 67`。基线 `eb9b179` 的浏览器脚本每调用一次 `check()` 就加一；单独拆开“历史范围为活动且控件已禁用”即可把计数从 67 变成 68。

Rust 入口现在核对隔离 HTTP 服务返回不同目录快照后，页面实际选中的主机、项目和渲染出的卡片。主机 B 的缓存目录缺少 `other` 时仍选中该项目，显示卡片 `other`。主机 A 的完整目录缺少 `empty` 时回到全部项目，显示 `active`、`last-active` 和 `legacy`。点击归档后，实际逐项请求只包含 `active` 和 `legacy`。失败草稿重试必须只提交一次到 `server`，复用原操作 UUID，成功后清除这份草稿。

| 隔离对照 | 原测试 | 修改后的测试 |
| --- | --- | --- |
| 同时检查值和禁用状态改成分开检查 | 失败，68 与 67 不等 | 通过 |
| 缓存目录仍包含应移除的 `other`，选项和卡片与缺项时相同 | 通过 | 失败，浏览器收到的前后两份目录实际没有移除任何项目 |
| 在看板渲染时漏掉最近目录中的活动缓存卡片 | 通过 | 失败，主机 B 的实际卡片为空，缺少 `other` |
| 重试时只关闭对话框 | 通过 | 失败，服务未收到重试请求 |
| 重试沿用同一 UUID，项目从 `server` 换成 `empty` | 通过 | 失败，服务收到的项目是 `empty` |

原测试和修改后的测试均通过正常路径。对照运行同一个 Rust 测试入口，浏览器驱动真实页面；故障只改隔离副本。原始观察、各组退出码及断言差异保存在本工作树旁的 `evidence/`。
