# A 保存回执与官方 UI 门禁

作者分支 `codex/fedora-a-card-save` 直接基于 `5f5d5d26addf432db0a1d834e0750d241052c032`。队列预留的基线已从远端 `main` 读回。Mac 交接头 `a301fe39d3df7f3c52283a07633e0fd58efdc8cc` 的六个补丁在 `e0ba3fa4d20dde4cb7997eb5ac946f0b5856595f` 上逐个等价，三个生产补丁保留原独审实现。Fedora 实现审阅头为 `dae41a48512873e8b2d21051207e321d7b0cebec`。

## 两个原失败

| 现场 | 当时的结果 | 复验 |
| --- | --- | --- |
| Mac 主机筛选 | `check-host-filter.mjs` 的 `Runtime.evaluate` 超过 10 秒，UI 全组 7/8。 | 原作者单跑筛选及重跑全组均通过，超时原因未确定。Fedora 在预留基线单跑筛选 60 项、Rust 几何与筛选组 1 项通过。 |
| Fedora 保存回执门禁 | 预留基线加原 A 时，保存脚本完成 69 个场景。Rust 包装器写死 64，官方 UI 全组 7/8。旧门禁却接受只上报数字 64 的脚本。 | 修复后从实际 `transfer.json` 读取成功场景，核对必需名称、非空、汇总一致及脚本退出码。官方 UI 全组 8/8，保存定向 1/1。 |

门禁校准使用相同 Rust 测试二进制。用无关名称替换 `wrong-host` 并维持总数 70、返回空清单、或脚本带完整报告退出 3，Rust 均退出 101。保留真实场景并新增一项时 71 项通过。新浏览器反例给出同主机另一 UUID 的回执，页面保持待核对，放行快照后恢复，原始保存只发一次。

## 四联回执

Fedora 的独立 Chrome 在本树 Rust 服务上把待审阅卡拖入已阻塞并输入两个空格。请求保留 `"  "`，回执、刷新前页面及最终数据库快照的备注均为 `""`。后三个卡片对象完整 22 个字段相等，版本均为 8，原生位置从待审阅变为已阻塞。11 个编辑场景成功，捕获 9 个真实写入回执；失败空草稿、取消、遗漏备注与等待中重复提交保护仍通过。开发服务已停止，浏览器进程组和 profile 均已清理。

Mac 首件的旧实现记录了 `"  "`、缺失回执卡、`"  "`、`""`；修复后首件三个卡片对象相等，版本均为 44。Mac 原失败与重跑日志分别保留。
