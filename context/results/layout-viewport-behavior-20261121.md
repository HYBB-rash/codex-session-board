# 原布局 48 项的裁决

保留 `test::ui_layout::long_content_and_project_filters_preserve_browser_column_geometry`。Rust 从 Chromium 的 `measurements.json` 核对真实窗口宽度、颜色主题、测得的列数和场景。浅色与深色分别覆盖五列和六列，1474px 验证短标题、长内容、两个项目、恢复全部、空搜索和长主机名，801、800、600、390、320px 验证长内容的横向滚动。增加其他合法视口也可通过。

浏览器读取实际筛选控件、可见卡片 ID、标题、目录、项目名、备注及详情展开状态。用各元素的字体实测标题中连续字符、目录、项目名和备注的单行宽度，确认超出卡宽；展开时逐项比对显示文本与输入。再测量列宽、标题换行、卡片底部、页面宽度及最后一列滚动后的边界。

| 同一 Rust 测试入口下的对照 | 原基线 | 修改后 |
| --- | --- | --- |
| 原样运行 | 通过 | 通过 |
| 加入 389px，保留原有宽度 | 52 与 48 不等，失败 | 全部通过 |
| 以重复的 390px 替换 320px | 通过 | 缺少 320px 实测，失败 |
| 长标题替换为短标题，其他长字段保留 | 通过 | 缺少长标题，失败 |
| 项目 `first` 显示同样数量的错误卡片 | 通过 | 实际 `layout-2`，预期 `layout-0`，失败 |
| 在 320px 用 CSS 强制标题单行 | 标题溢出，失败 | 标题溢出，失败 |

初审另发现标题和备注设为 `display:none` 时仍能从 DOM 读到文字，零宽高也通过了上限检查。最终版本核对元素可见且有实际尺寸。复审分别隐藏标题、项目标签和备注，三组均被检出。标题的连续片段由浏览器按 `min-content` 自然断行测量。将 400 个 `x` 换成 400 个 `Ж`，实测片段宽 5403.97px、卡宽 257.20px，全部场景通过。

基线原始补丁、测量和 Rust 退出码位于工作树旁的 `evidence/layout-controls/old/`。最终代码对照位于 `evidence/layout-width/` 和 `evidence/layout-visibility/5b9c839/`。两项改动分别归属目录和布局，生产页面、需求及测试 ID 均沿用基线。
