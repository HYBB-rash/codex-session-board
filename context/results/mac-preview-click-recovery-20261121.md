# macOS 嵌入预览首击

`verify_source` 运行 `44880119583` 的 Linux 和 macOS 使用同一源码 `b4d8b23e3236cb91db74c81ce5ab89919ba51682`。Linux 通过，macOS arm64 只失败了 `test::ui_layout::reply_preview_preserves_scroll_focus_and_rejects_late_bodies`。HTTP 场景已完成。原报告没有鼠标命中元素或宿主消息，能定位到嵌入场景等待首次本机预览请求，无法据此判断当次是哪一次布局或输入路由变化。

| 对照 | 观察 |
| --- | --- |
| MacBook Pro 实机重跑同一旧源码 | macOS 27.2.1 上 HTTP 后接 MCP 六次通过，单跑 MCP 六次通过。同机一次事件记录显示 iframe 原点 `(0,0)`，标题中心 `(633.5,243)`，真实点击命中本机卡并发出预览请求。CI 为 macOS 26。 |
| 移动宿主的 iframe，保持卡片与后端不变 | Linux 把 iframe 顶部下移 120 像素，子页目标为 `(628.5,243)`。旧脚本向主页面派发同一坐标，子页收到 `(628.5,123)`，点击落在导航栏。本机请求为零。单跑 MCP 也失败。只换算坐标后，相同嵌入页面发出一次本机请求。 |
| 滚动容器裁切长标题，只露出底部 8 像素 | 独立实验中完整矩形中心 `y=190` 命中列头，可见区域中心 `y=207` 命中标题并发出请求。把上一页拖动流程移除未单独复现故障。 |

修复后，嵌入宿主为页面保留 48 像素顶边。回放用 iframe 的实际位置换算主页面输入坐标。首击前计算标题、列表和视口的可见交集，先将物理指针移到候选点，读回浏览器实际悬停目标，再派发一次按下和释放。日志记录可信点击的卡片 ID 与坐标；随后仍要求 fixture 收到本机的预览请求并挂起回执。HTTP 和 MCP 在每个场景结束后关闭自己的页面，下一场景独立开始。
