# 在 Codex Enhancer 中完整重写会话看板

在当前仓库 `codex-enhance-demo`，使用 TypeScript 完整重写 `HYBB-rash/codex-session-board`，让用户从 Codex 窗口的 Enhancer 侧栏打开看板，管理本机和已连接远程主机的会话。本轮交付 Linux x86_64 可安装产物和逐项验收证据，以 Fedora 44 x86_64 真机验收独立副本和原地安装两种方式的安装、运行、更新、回退和卸载。

## 源码与范围

以原仓库提交 `2cc4e6bb4e03d7cfabce0733a91a328004a9f3fc` 为行为基线。本机已有检出 `/home/herman/文档/notion-program`。按提交读取源码、测试和配置，尤其是 `assets/board-start.ts`、`assets/board-operations.json`、`src/main.rs`、`src/store/`、`tests/native_authority/` 和 `acceptance/requirements.json`。代码与早期说明冲突时，以该提交的实现和测试为准。先读本仓库 [接入调查与实测](session-board-typescript-investigation.md) 和 [安装说明](../README.md)。

复用上游 Vue 3、TSX 和 TypeScript 组件，保留用户已熟悉的布局与操作。产品前后端、业务运行时和随包运行的更新、迁移逻辑用 TypeScript 实现。Rust 版本和独立 Python 验收模型可用于对照，新产品运行不依赖旧看板二进制。实现遵循本仓库 `AGENTS.md`。

## Codex 接入

- 保留现有的**副本安装**作为默认方式。从已打包的客户端创建独立副本，在副本的 `app.asar` 启动入口加入 Loader，加载外部 Runtime。副本使用自己的用户配置和连接，系统安装保持原样。
- 提供显式选择的**原地安装**，在兼容的现有客户端中加入 Loader。用户安装一次并重启 Codex，之后仍从原图标打开原客户端，沿用登录、项目、会话、SSH 连接登记及 Codex 自身更新。两种方式都以已打包客户端为目标，保留 Codex 开发源码仓库。README 分别说明适用平台和构建、所需权限、安装、启动、升级提示和卸载方式，待验证的组合标明状态。
- 本机与远程操作均复用该窗口已经拥有的连接。主机连接和 SSH 生命周期由 Codex 管理。删去旧插件为寻找后台、匹配父进程或另建 SSH 代理所需的逻辑。PWA、MCP、CLI 需要实时数据时也遵守这一约束；宿主离线时，准确区分缓存和可操作数据。
- Fedora 桌面 `26.1111.71704` 的临时页面探针已经从同一窗口向本机和 MacBook Pro 发出 `thread/list`、`thread/read`，并核对过请求、回执主机和会话 ID。探针已撤下。将已证实的读取方式接入正式页面，主机 ID、会话 ID、构建哈希文件名及本机路径均从运行环境取得。
- 用类型区分会话的实际主机、侧栏条目、当前账号、逻辑分区和各主机的分区 ID。已有实测中，侧栏标成 `local` 的条目实际位于 MacBook Pro。写操作以当前宿主确认的目标为准。只向页面提供看板需要的操作。

## 第一个实现检查点

先交付一条真实可用的操作链。打开正式看板页面，读出本机和远程卡片。在两端各用一张专用测试卡，从看板拖入另一个受管分区，在 Codex 原生侧栏看见变化，并从目标主机独立读回实际位置。随后从侧栏移回，检查旧表单被拒绝、备注保留。记录同一张卡的主机、会话 ID、原位置、目标位置和读回结果。回执丢失时先查实际状态。

这一步同时检验能否复用宿主的逻辑分区服务并移除旧插件的临时会话校准。页面动画、成功提示和后端单次应答都不足以签收移卡。验证通过后直接继续其他功能。若宿主确有能力缺口，保留失败证据，继续可独立完成的工作。

## 原地安装、卸载与升级兜底

先在 Fedora 验证原地模式。`26.1111.71704` 已在 Fedora 隔离副本验证本机与远程原生移卡。现场只读核对确认，日用客户端的 `app.asar` 由 RPM 管理，文件 SHA-256 与 RPM 记录一致。归档和目录均由 `root` 所有。内存实验确认现有 Loader 能让原启动代码在 Runtime 同步抛错后继续执行，但没有构建兼容性门槛。模拟新版移除旧启动入口时，现有 `status` 会在读取旧入口时抛错。这些结果用于确定原地方案的验收范围。[副本验收](session-board-typescript-acceptance.md) · [Loader](../src/installer/constants.ts#L6) · [状态检查](../src/installer/status.ts#L23)

1. 将上游 31 条基础需求逐项绑定到新实现，另行验证原生分区、远程操作和新增的 Enhancer 接入。对相同输入，对照新旧实现的状态、版本、回执和持久数据。优先覆盖同 ID 跨主机、账号或连接切换、迟到回执、重复提交、历史记录及重启。保留独立模型和原断言。
2. 在真实看板中验证轮次状态更新、预览、筛选、拖放、归档、断线重连。页关后再打开，订阅不会重复，观察器、标题重试和定时归档按选定配置继续工作。写入验收仅使用本轮创建的专用测试数据或隔离夹具；测试副本与日用窗口连到同一远端时，已有远程会话仍属于用户。
