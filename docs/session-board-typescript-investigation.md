# 会话看板 TypeScript 重写调查

**新看板采用 Enhancer 方案，直接复用当前窗口已有的本机和远程连接。**  
Herman 已澄清允许的修改范围：复制已打包的客户端，在副本的 `app.asar` 启动入口加入 Loader，加载外部 Runtime。系统日用安装和 Codex 开发源码仓库均在修改范围之外。[现有安装器行为](../README.md)

首选入口是副本内的 Enhancer 侧栏页面。上游 MCP App 的 `global` 入口可留作兼容。2026 年 11 月 22 日通过第一方桌面工具读取 MacBook Pro 的结果，仅用于对照桌面能力。

## 已有连接能替代哪些插件工作

| 原插件承担的工作 | 新看板如何处理 | 证据 |
| --- | --- | --- |
| 寻找本机后台和侧栏 socket，核对父进程及对端 PID，失联后再发现 | 桌面持有连接。按当前账号、目标主机和连接实例请求；实例被替换后重新取快照 | 当前桌面包的连接注册表按 `hostId` 保存实例。分区服务核对连接状态，能拒绝过期操作 |
| 自行启动 SSH、代理、远程探针，处理握手、超时和子进程回收 | 连接登记和建立交给 Codex。看板只读取宿主现有的在线主机，离线时可显示上次快照 | 副本自己的看板页面已通过 MacBook Pro 连接读回列表和详情；日用桌面还独立读回过远程归档历史 |
| 猜测远程逻辑分区与后台分区的对应关系，必要时新建专用空会话校准 | 优先调用桌面自己的逻辑分区服务。由它解析各主机的分区；看板保留移卡后的独立读回 | 桌面包记录逻辑分区、各主机的 `hostSectionIds` 和副本绑定。新扩展能否通过同一服务往返移动远程卡，仍待实测 |
| 由 MCP 插件进程托管 HTTP、观察器和定时归档 | 观察器归属取决于插件能取得的授权接口。PWA、CLI 和 MCP 若需实时数据，也依赖这条通道 | 桌面进程退出后，已有连接即不可用。后台观察与页面关闭后的行为需要分别验收 |

**看板仍拥有人工选择、备注、新输入复核、标题重试和归档批次。**  
Codex 知道会话归哪台主机、某轮是否结束，却不知道用户上一次确认归档之后是否又看过新输入。归档写入成功但回执丢失，重开只核对结果，这项约束也属于看板。连接恢复时重新读快照，期间收到的旧结果不能覆盖新状态。

## 日用桌面只读实测

下表是单独通过日用桌面自带的 `codex-app-tools` 取得的对照结果。它覆盖了远程数据，但不计入 Enhancer 页面的远程验收。

| 检查 | 观察结果 |
| --- | --- |
| 枚举项目并按主机读历史 | 桌面列出了本机项目和同一台 MacBook Pro 上的两个项目。本机历史返回了当前活跃会话；远程活动历史第一页与第二页各得到不同会话，两页都返回该远程主机 ID |
| 区分活动与归档 | 按相同远程主机读取归档历史，得到另一条会话及下一页游标。活动和归档分别分页 |
| 核对远程最后一轮 | 对一条 `notLoaded` 的远程会话读取即时快照，返回实际主机、已完成轮次和同一轮的 `final_answer`。这为答复预览提供了比会话摘要更完整的依据 |
| 比较侧栏与实际主机 | 远程两页中的两个会话 ID 同时出现在桌面“待审阅”分区的 `local` 条目。挑其中一个，只以 `local` 为目标调用 `wait_threads`，实际回执仍指向 MacBook Pro |

最后一项决定写操作的身份规则。侧栏条目可以作为展示和导航线索。移卡、改标题和归档需要以宿主读回的实际主机、会话 ID 和当前账号为准。一次读回已经纠正了主机，仍不能推断其他会话也使用同样的别名规则。

## 兼容入口与数据权限

**原装客户端已有全局侧栏入口；给看板展示页面与授权它读取会话是两件事。**  
OpenAI 的 *Plugin Extensions / Sidebar apps* 给出了 `openai/ui.entrypoints` 的 `global` 入口。上游 `src/mcp.rs` 的 `tools_for_mode` 已用相同声明注册看板。TypeScript 版可以保留这个入口和 Vue 界面。

核查了 *Add UI to your MCP server*、*Remote connections* 和本机 Fedora 桌面包 `26.1111.71704`。在当前包的 `webview/assets/async/834146.da672ba7be.js` 中，普通 MCP App 的 `tools/call` 从宿主接收该应用绑定的 server 和工具范围，核对工具后再分派。上游 `assets/app-bridge-entry.mjs` 也据此调用看板自己的工具。不能据此把当前对话可以调用的第一方 `list_threads` 当成第三方页面已有的权限。

上游 `src/rpc/authority.rs` 另外实现了从 `CODEX_APP_SERVER_WS_URL` 读取启动方传入的后台地址。这是核查本机能力时可沿用的线索。该变量是单个端点，上游对远程主机另走 `remote_binding`；现有证据尚未表明第三方可通过该端点取得窗口的远程连接或原生侧栏操作。

在这版桌面包中，可用下列入口复核判断。文件名随构建变化。

## 接入难点与实测

**桌面侧栏写入和会话后台读回必须指向同一个客户端、同一台主机。**  
上游 `src/native_sections/direct.rs` 的 `move_checked` 先读原位置，经桌面操作 `move_thread_to_sidebar_section` 写逻辑分区，再通过目标后台的 `thread/read` 映射并核对结果。远程启用原生分区时，`src/remote/instances.rs` 继承该配置，`src/app/native_mapping.rs` 对目标主机的映射进行校准。早期远程说明里“远程列不使用桌面分区”的描述已经落后于这段代码。原插件还会核对共享后台的进程身份。换成窗口扩展后，原来“启动 MCP 进程的父进程就是后台”的依据也随之改变。

本次从 Fedora 的 Codex Desktop `26.1111.71704` 随包二进制 `0.169.1` 和命令行 `0.171.0` 分别生成了 App Server 的 TypeScript 类型，两者连 `thread/list` 的参数都不同，后者多了 `includedThreadIds`。随包版本在实验协议中给出 `project/list`、`project/read` 和项目补登记所需的 `projectId`。桌面资源中也能找到侧栏移动操作的名称。协议类型和包内名称都不能证明新扩展已经获得运行中窗口的连接。

初次调查使用临时空配置启动随包后台，实际完成了 `initialize`、`thread/list`、`thread/loaded/list` 和 `threadSection/list`。结果分别为两个空会话列表和一个分区。这个实验验证了当前构建的只读协议。日用窗口的验证另见上文。实现可使用目标版本生成的协议类型，运行时仍需核对宿主、主机、账号以及可用能力。

**现有前端能复用，但其页面假定自己占有整个文档。**  
上游 `assets/board-start.ts` 通过 `window.boardRequest` 或 HTTP 发出请求，用 `document.getElementById` 查找元素，模块加载即挂载组件并每四秒刷新一次。原装客户端的 MCP App 为这套界面提供独立页面，可沿用上游挂载方式。验收覆盖反复开关、切聊天、快捷键、拖放和回复链接；观察、标题重试和定时归档的生命周期须单独核对。

**归档、远程和迁移的失败行为比正常流程更容易丢。**  
上游在归档前复核输入和位置，把未提交、已拒绝、已提交待核对、已确认分别保存。远程卡片使用主机与会话的组合身份，断线、来源变化或不完整分页都可能改变可执行的操作。迁移还需要保存未连接主机的数据。此次在系统 Node `22.23.1` 上用合成 SQLite 库验证了在线备份能读回仍在 WAL 中的已提交备注；桌面内置运行时的 SQLite 能力、全量旧库迁移和崩溃恢复仍需单独验证。

## 建议的首次验收

1. 本机与远程列表、详情的页面直读已通过。实现完整看板时保留这组回归，并另行核对轮次与最终答复。
2. 从看板移动这张卡，在 Codex 侧栏看见变化，并从目标后台独立读回。从侧栏移回后，旧表单被拒绝，备注不被覆盖。再用一台已连接的远程主机重复验证，断连后读缓存、拒绝过期写入。
3. 用相同输入驱动上游 Rust 和新 TypeScript 实现，对照状态、版本、回执和持久数据。覆盖重启、新输入、迟到回执、同 ID 跨主机、答复预览、批量归档丢回执，以及旧库带 WAL 的迁移。保留独立参考模型。
4. 在决定支持的宿主上逐项验收桌面入口、远程项目新建、网页/PWA、MCP、升级和回退。上游 `acceptance/requirements.json` 的 31 条是基础契约；还要覆盖原生分区和远程专项。上游 Vue 迁移在 `70ac74e` 记录了 Linux 937 项自动检查通过、31 条中 17 条通过、14 条缺目标环境证据。新实现需要自己的桌面、远程及平台验收记录。
